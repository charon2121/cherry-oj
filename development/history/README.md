# 旧工作系统的迁移记录

2026-10-03，开发文档系统改为明确调用仓库 `$dev-work` 后使用。

- 62 个 WORK 保留目录、编号和主入口路径；主入口换成短说明。
- 原主文档另存同目录 `90-history-WORK-xxx.md`，原有附件与 `flow.json` 原样保留，总计 574 份历史文件。
- [work-system.zip](./work-system.zip)保存迁移前的入口规则、规范九章、模板、Schema、编号表、总览、工具与测试。ZIP 内按原仓库路径组织。
- [migration.json](../migration.json)保存每份历史文件的 SHA-256、原 WORK 状态与闸，以及系统快照摘要。`scripts/work check` 验证原件未丢失或变化。

旧文件里的命令、状态机、签闸和强制文档规则均是历史记录。它们不再对当前工作生效。WORK-060/061 存在“已经实施并有验证、正式闸仍待签”的差异，WORK-033/058 的状态与闸也不完全一致；迁移保留这些事实，不修成看起来完成。

本次最初按旧规则准备了 WORK-062，之后用户明确豁免旧流程，并要求迁移。其早期方案和未签闸一并保留，新入口说明最终做法，旧方案不再是本次实施边界。

继续旧工作：先读短说明和必要旧依据，再按当前授权实施；只有明确调用 skill 才进入文档流程。写新结果时更新当前入口或新增附件，勿修改历史原件。快照可用于核对与恢复，恢复操作需按当时的实际任务范围执行。
