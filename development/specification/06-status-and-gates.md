# 6. 确认与结果

启用 skill 后有两个自然的对话点：

1. 开工前，用户看到简短说明后确认目标、范围和关键代价，并允许实施。
2. 收束时，Agent 展示实际结果与证据，用户判断是否接受。

不再运行 `gate`、维护阶段状态或要求手动签署命令。已有聊天授权按原范围生效；明确免除某次确认时，不为了满足模板再次询问。范围扩大、关键代价改变或缺少真正影响决定的信息时，先补充说明并解决对应问题。

Agent 可以写“已实施”“测试通过”“待人工体验”，不能自行写“用户已接受”。一次普通开发请求在未启用 skill 时，不被这里的文档回合约束。

旧 WORK 的状态和闸只作为历史事实保存；迁移、校验和 CI 都不补签，也不自动推导最终接受。
