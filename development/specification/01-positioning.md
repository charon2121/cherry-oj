# 1. 核心定位

## 1.1 要解决的问题

人的注意力有限。系统应让人看清本次变化、边界、代价和验收结果，让 Agent 找到实施依据、
读写范围和真实证据。文件齐全不能证明目标正确；签署记录也不能证明人理解了材料。

## 1.2 统一闭环

人的意图 → 主文档与必要调查 → 人确认并授权 → 实施与复核 → 结果及证据 → 人验收。
重要新结论按需沉淀，普通工作不强制产生记忆文件。

## 1.3 流程的目的

默认一份主文档加一份证据。信息职责分清即可，不要求各占一个文件。
复杂度来自实际方案、协作或交付依赖；风险优先增加验证强度，不自动增加文档种类。
历史工作保持原格式，避免整理工具反过来制造批量迁移任务。

## 1.4 基本行为准则

- 不把假设写成已确认决定，不把代码写完说成验收通过。
- 人审核目标、边界、重要取舍与结果；Agent 负责实现分析和证据；脚本负责确定性约束。
- 普通需求的审核内容以一屏为目标，复杂需求完整展示实质代价，不靠省略风险达到短小。
- 文档审核与实施保持两个回合，两道闸只能由人签署。
- 当前事实只存一处，其他入口读取或引用；格式通过不等于语义正确。
