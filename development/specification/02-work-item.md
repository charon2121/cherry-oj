# 2. 工作记录

一项工作是一个可以说明目标、划定范围并判断结果的改动。启用 skill 后，在 `development/works/` 下建立日期与短名目录；已有 WORK 继续沿用原目录。

每个工作必需一份 `00-work.md`，从目标到交付持续更新，不为讨论、实施和验收各复制一份摘要。五种类型为功能 product、基建 infra、修复 fix、维护 maintenance、改进 improvement；`feature`、`bug` 等可按这些类型理解，具体流程见[第 4 章](./04-workflows.md)。

范围用普通语言写清涉及的模块、不能破坏的行为与限制。只有确有独立委派时，才在任务附件写明确可读、可写和禁止路径，子任务不能扩大已确认范围。

数据变化、公共接口、安全权限、跨模块依赖和难以回退的改动需要更充分的说明与验证；不再给风险和影响面维护枚举字段。会改变目标或代价的未知写进主文档，解决后再实施依赖它的部分。
