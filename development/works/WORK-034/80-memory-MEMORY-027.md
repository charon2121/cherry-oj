# MEMORY-027：下载版主导的双主题设计系统重建经验

## 背景

用户认可的下载版 Cherry OJ Design System 与仓库现有系统虽都受 Linear 启发，但前者通过完整的色阶、密度、
构图、组件状态和 UI kit 呈现出一致观感，后者只在 token/材料层局部合规，实际页面没有形成同一视觉语言。

## 决定与原因

本次实施验证了三层职责：来源快照负责暗色视觉证据，中文合同负责生产约束与浅色推导依据，Web 代码包负责
运行时；原型 JSX 不能直接成为生产实现；token、组件和页面必须分别验证。来源只有暗色不代表产品必须删除
浅色，输入材料的边界不能替代用户的产品决定。

## 尝试与教训

已经由实现和自动验证确认的教训：

- “Linear-inspired” 标签不能证明页面符合目标，必须用具体 UI kit、组件状态和全路由截图验收。
- 全站重建应按 Foundation→组件→Shell→业务页面分阶段保持可编译，不能长期运行旧/新两套可选 UI；同一
  系统下的暗色/浅色主题则是正式产品能力。
- 浅色不能机械反色，也不能复制一套组件；应与暗色共用结构和非颜色 token，只在完整主题合同中提供颜色与
  elevation，并逐状态验证层级和对比度。
- 视觉参考中的 inline style、随机 id、可点击 div、远程 CDN 和手绘 SVG 是原型手段，不可绕过生产工程约束。
- 可访问性适配需要显式记录；保留下划线、语义链接、稳定 id 与状态冗余不等于背离视觉目标。
- 页面跳动不能靠高度动画或假内容掩盖，应定义滚动容器和用户锚点后用真实几何验证。
- CLAUDE/AGENTS 只负责路由到设计合同，不复制规则正文；否则文档再次漂移。

零样例问题最终也证明：真正稳定的修复是步骤切换后把内容锚定到拥有滚动权的 `#admin-main`，并用相对几何
断言；给空态填假高度只会掩盖滚动语义。工作台 757.24/256.14 kB 与 WORK-033 基线基本持平，说明视觉系统
替换可以不重新引入 Monaco 级别的体积成本。

## 已知问题

Pure White 没有可逐像素复制的下载版来源，只能用同构合同、对比度和人工观感共同约束。工作台 chunk 仍有
500 kB warning；真实读屏器、中文输入法候选窗和生产数据仍待后续环境验证。MEMORY 在 VERIFY-035 和用户
验收前保持 `draft`，不把尚未签署的审美判断写成最终事实。

## 重新考虑条件

若用户要求更多主题、提供浅色视觉真源、来源包发生变化、生产可访问性与目标视觉无法兼容、全站迁移显著
超出性能预算，或业务路由/产品能力发生变化，应重新打开 DECISION-019 与 DESIGN-028，而不是继续累积
页面例外。
