# CHANGE-012：统一后端服务配置

## 为什么做

五个后端服务因启动入口和配置来源不一致，反复出现重启后缺少密码或服务凭据的问题。本轮让开发者准备一次本地配置后就能直接启动，同时保留容器环境灵活调整配置的能力。

## 当前状态

WORK-044/045 仍有真实运行验收缺口；五服务存在不一致的 YAML 默认值、dev 预置、IDE 参数、私有 .properties 导入和环境变量来源。此前修复多次只覆盖局部配置，未保证完整调用链。

## 当前问题

配置字段不齐、秘密默认值入库、私有配置加载依赖入口；测试与部署存在误用本地值的风险。本轮按用户“重构当前后端所有配置文件”的要求执行五服务配置治理，不扩建全栈配置框架。

## 目标状态

- REQ-001：覆盖五服务本地开发、测试及 Compose 部署配置，保留环境隔离。
- REQ-002：统一 application.yaml、application-local.example.yaml、application-local.yaml；前两者入 Git，最后一个仅存本地。
- REQ-003：本地默认 local Profile，直接运行主类不需要配置参数、环境变量、生成器或包装脚本。
- REQ-004：基础配置列全项目字段、环境变量映射和安全默认值；必要配置缺失/非法时明确指出问题，验证实际加载效果。
- REQ-005：Compose 通过环境变量选择非 local Profile 并覆盖配置，适配 dev/test/prod；不通过命令行配置参数启动服务。
- REQ-006：完整迁移本地密码、凭据、地址和功能配置，核对配对；清理旧导入及参数，秘密不进 Git/JAR/镜像，测试不读本地文件。

## 不变条件

- REQ-007：不改服务业务边界、权限、公开接口或判题语义，不改数据库密码，不降低鉴权和限流。
- REQ-008：不修改 Web 业务、Go 判题或沙箱实现；不以配置治理替代 WORK-044/045 的实际验收。

## 影响范围

apps/server 五服务资源配置、POM 打包排除、必要配置校验、相关测试、共享 IDE 配置、后端 Compose 示例与说明、忽略规则。用户主目录不存项目配置，不新增支持模块或配置中心。

## 风险

默认 local 会影响未指定 Profile 的测试，必须审计并隔离；私有资源不能被 Maven/IDE/Docker 构建带入产物。迁移前备份，冲突不覆盖，完整保留有效配置。

## 回归检查

- AC-001：五服务不带配置参数、环境变量、生成步骤即可从开发类路径读取 application-local.yaml；实际启动按可用环境验证。
- AC-002：示例字段完整可理解，迁移前后本地值及配套凭据一致，没有秘密默认值留在跟踪文件中。
- AC-003：Compose 非 local Profile 和环境变量覆盖实际验证，未配置秘密不回退为开发值，不要求 -D/-- 参数。
- AC-004：后端现有测试与鉴权/功能回归通过，测试不读本地秘密、不连接开发库。
- AC-005：从含 application-local.yaml 的开发树构建，发布 JAR/镜像不含私有配置，覆盖重打包及残留资源场景。
- AC-006：移除旧导入、IDE 参数和重复入口，有私有备份可回退；不改数据库、不误停用户进程，记录全部未验证项。
