# FEATURE-006：重新设计登录页视觉与体验

## 为什么做

现有登录页功能完整，但页面主体只由一个居中表单构成，视觉层级与空间利用不足。需要在不扩大登录
能力的前提下，让它成为 Cherry OJ 产品体验的一部分，并提高首次进入时的识别度与完成信心。

## 使用者

- 尚未登录、主动进入登录页的访客。
- 访问受保护页面后被安全引导到登录页的用户。
- Session 过期、退出登录或首次登录流程中需要重新认证的用户。

## 入口

用户通过 Header 的“登录”、直接访问 `/login`，或从需要身份的页面重定向进入；保留安全的
`returnTo` 参数，登录成功后回到允许的原目标或首页。

## 正常流程

1. 用户进入登录页，先看到明确的 Cherry OJ 身份、登录目的和账号密码表单。
2. 用户输入用户名和密码，可按现有方式切换密码可见性。
3. 用户提交后看到尺寸稳定且可读的登录中状态，不能重复提交。
4. 成功后沿用现有 Session 缓存、首次改密和安全返回路径规则。
5. 失败时在表单上下文中看到可理解的原因，输入保持，修正或稍后重试。

## 业务规则

- REQ-001：页面必须保留用户名、密码、密码显隐和“登录”四项现有核心能力。
- REQ-002：登录必须是页面唯一主要动作，不能出现注册、找回密码、记住我、社交登录或二维码登录。
- REQ-003：必须保留现有 Header、Footer、`/login` 路由和安全 `returnTo` 行为。
- REQ-004：成功后的 Session 更新、首次改密跳转、ADMIN/USER 跳转及 401 处理不得改变。
- REQ-005：空字段、服务错误、限流、网络/契约错误和提交中状态必须保留现有语义与恢复能力。
- REQ-006：视觉构图必须减少“表单孤立在大面积空白中”的感受，并与主页的专注练习语言保持一致。
- REQ-007：只能使用当前设计系统 semantic token、共享组件和 Lucide 图标；shadcn/ui 已有能力优先复用。
- REQ-008：装饰或辅助文案不能虚构题量、通过率、用户数、排名、证言或尚未交付的产品能力。

## 边界与失败

- 已登录用户访问登录页的现有路由行为不在本工作中改变。
- 登录失败后不得清空密码以外由现有实现决定的输入，也不得跳离页面或用只靠颜色的方式表达错误。
- 320px 下辅助视觉可以隐藏、缩短或重排，但品牌、说明、字段、错误和登录按钮必须完整保留。
- 未知或过长错误文案需要换行并保持按钮可见；重复点击在 pending 期间仍被阻止。

## 要求

- REQ-009：用户名和密码继续使用真实 label，错误与字段/表单建立可访问关系，密码显隐有可访问名称。
- REQ-010：键盘顺序必须符合视觉顺序，焦点清楚；200% 缩放和 320px 下不出现横向溢出。
- REQ-011：两个登记主题必须呈现相同信息和状态，不在页面代码中判断主题 id 或写 raw 颜色。
- REQ-012：页面不得记录、回显或暗示保存密码；不得改变 Cookie、CSRF、Session 或请求日志规则。
- REQ-013：非必要装饰在辅助技术中隐藏，reduced-motion 下不依赖位移或动画理解状态。

## 验收标准

- AC-001：访客进入 `/login`，无需滚动即可识别 Cherry OJ、看到两个字段并找到唯一主要“登录”动作。
- AC-002：空提交、错误凭据、429 和服务失败均显示可读错误，修正后可以再次提交。
- AC-003：快速连续提交只产生一次登录请求；pending 文案可读且控件尺寸不跳变。
- AC-004：登录成功继续遵循安全 `returnTo`、首次改密与角色规则，现有登录 E2E 全部通过。
- AC-005：桌面与 320px、两个主题、200% 缩放、长中文错误下没有横向溢出或关键内容裁切。
- AC-006：仅键盘可输入、切换密码显隐、提交和恢复；焦点、label、错误 alert/关联可被辅助技术识别。
- AC-007：源码门禁确认没有 raw 色值、主题分支、透明状态色或设计系统外组件合同。

## 不做什么

不新增注册、忘记密码、记住登录、第三方/二维码登录、验证码、主题切换或账号申请流程；不修改认证
API、Session、CSRF、安全返回路径、权限、Header/Footer 结构、主页、管理端或后端。
