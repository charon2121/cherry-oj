# FEATURE-009：统一页面任务优先布局并移除状态占位

## 为什么做

当前用户端和管理端页面普遍先展示一组“栏目名、页面标题、说明文字”，真正要操作的筛选器、表单、列表
或工作台被推到下方；同时导航栏与首个有效组件之间存在 24～80px 多套距离。管理端还把“返回用户端”
作为页头独立按钮，并让左侧菜单随整页滚动。这些做法占用首屏、重复导航已经表达的信息，也让不同页面
像由不同布局规则拼接而成。

首页的“REST API 已连通”曾用于早期连通性验证，现在不再提供用户价值；继续保留会把技术探针误当成
产品内容。本工作删除它及专用接口，并建立长期页面布局规范，让页面首先呈现任务本身。

## 使用者

所有访问 Cherry OJ 的访客、普通用户与管理员。普通用户希望打开页面后立即看到题库、表单或题面；
管理员希望在稳定的管理壳层中处理表格和工作台，不因内容滚动失去导航位置。

## 入口

现有用户端与管理端所有路由保持入口和地址不变。管理员仍从用户端账号菜单进入管理中心，并从管理端
账号菜单返回用户端；本工作不增加新路由。

## 正常流程

1. 使用者通过现有导航进入页面，导航下方以统一的 24px 间距直接出现筛选器、表单、列表、题面、工作台
   或真实状态组件，不再先读一段通用页面介绍。
2. 管理员在桌面管理端滚动中央内容时，页头和左侧管理菜单保持原位；窄屏继续通过现有 Sheet 使用菜单。
3. 管理员需要返回用户端时打开账号菜单并选择“返回用户端”，不再占用页头的独立位置。
4. 首页不再请求或展示 REST 连通状态；Gateway 也不再提供专用 `/api/status` 产品接口。

## 业务规则

- REQ-001：删除首页 REST 连通状态组件及其查询、测试和 E2E mock；删除 Gateway `/api/status`
  Controller、DTO 与定向测试，并从 OpenAPI、生成 Web 类型和服务端工具链说明中移除该资源。健康检查
  继续使用既有 Actuator，不新增替代的浏览器探针或兼容端点。
- REQ-002：用户端和管理端功能页面禁止在真实任务组件之前展示独立的“栏目 eyebrow + 页面 H1 + 页面
  描述”介绍块，也禁止用只重复当前导航项的可见标题填充首屏。页面第一个可见主体必须是筛选/操作区、
  表单、列表、业务对象标题与状态、题面、工作台或确有意义的提醒。
- REQ-003：REQ-002 不删除业务内容本身的语义：题目/版本名称、表单 legend、组件/区块标题、列表
  caption、登录表单身份、404/403、加载/空/错误状态标题均可保留；必要的页面名称通过文档标题、路由
  元数据或视觉隐藏标题提供，不能为了视觉规则损害语义结构和读屏导航。
- REQ-004：用户端和管理端所有由固定导航壳层承载的页面，导航栏实际底边到首个可见主体的上边距统一为
  `--ds-space-6`（24px），不随路由或断点改成 32/40/48/64/80px。组件内部、业务对象标题与内容之间
  的间距仍按其自身合同决定。
- REQ-005：管理端页头移除独立“返回用户端”按钮，在已登录管理员的账号菜单中新增同名入口；用户端
  ADMIN 账号菜单中的“管理中心”、修改密码、退出登录及主题切换行为保持不变。
- REQ-006：桌面管理端使用视口高的 Header/Sidebar/Main 壳层，文档本身不随业务内容滚动；只有中央
  `main` 是页面内容滚动容器，左侧菜单保持原位。窄屏仍隐藏桌面侧栏并使用现有可关闭 Sheet，不改变
  导航层级、当前项、焦点恢复和权限 guard。
- REQ-007：把“任务优先页面构成”、24px 壳层内容起始间距、账号菜单跨空间入口和管理端滚动所有权写入
  `docs/design-system.md`，作为后续页面长期规范；实现应通过共享 Shell/Layout 边界落实，不允许每个
  页面复制一套 magic spacing。

## 边界与失败

- 首页移除介绍块和状态组件后，只保留真实、条件成立的业务提醒；没有提醒时不新增营销卡片、假数据或
  替代探针。主导航继续承担进入题库等任务的入口。
- API 与唯一 Web 消费者在同一交付中删除，不保留 410/重定向；若仓库外仍有调用方，需在意图审核时提出。
- 管理主内容很短时不制造滚动条；很长时滚动中央 main。键盘聚焦、skip link 和路由内容不得被固定页头
  遮挡。
- 动态业务标题与异常/空状态不是“页面介绍”，不得机械删除。

## 要求

- REQ-008：320px、桌面、200% 缩放、键盘、两个主题、forced-colors 和 reduced-motion 下，首个任务组件
  不被页头遮挡，页头入口不溢出，管理侧栏与中央滚动可用；页面仍有可读的文档标题/语义标题。删除状态
  接口不得削弱 Actuator 健康检查、认证、CSRF、requestId 或其它公开 API。

## 验收标准

- AC-001：仓库生产代码、OpenAPI、生成类型、Gateway 测试和 Web/E2E 中不再存在 `/api/status`、
  `SystemStatusPanel` 或“REST API 已连通”；首页加载不发出该请求，现有 Actuator 健康端点仍通过回归。
- AC-002：逐页审计首页、题库、题目详情、登录、修改密码、403/404、管理 Dashboard、用户账号、题目管理
  和题目工作台；功能页面不再以通用可见 title/desc 介绍块开场，业务对象、组件和状态标题按 REQ-003 保留。
- AC-003：在 320px、桌面与 200% 缩放抽查用户端和管理端各类页面，导航底边到第一个可见主体均为 24px，
  路由切换不改变该距离且没有内容被遮挡或横向溢出。
- AC-004：管理端页头不再显示“返回用户端”；管理员打开头像菜单可以找到并通过指针/键盘进入 `/`。
  用户端“管理中心”、修改密码、退出登录、主题切换以及登录态加载/失败 UI 不回退。
- AC-005：在内容高度超过视口的管理用户、题目与工作台页面滚动中央内容，Header 和桌面 Sidebar 的位置
  保持不变，浏览器文档滚动位置不承担业务滚动；移动端 Sheet 仍可打开、选择、关闭并恢复焦点。
- AC-006：`docs/design-system.md` 明确记录 REQ-002～REQ-007 的长期规则，能区分“禁止通用页面介绍”
  与“允许业务/组件/状态标题”，并给出共享布局而非逐页 magic number 的消费要求。
- AC-007：Web 定向测试、`npm run check`、`npm run build`、Storybook build、Playwright 全量和设计
  系统文档 check 通过；服务端 Gateway 定向测试与 `./mvnw clean verify` 通过，OpenAPI 生成检查无漂移。
- AC-008：实施范围复核确认没有改变路由地址、题目/用户业务 API、认证授权、主题合同、导航层级、数据或
  数据库；只删除已声明的 status 契约并调整页面构成、壳层入口、间距与滚动所有权。

## 不做什么

- 不重新设计主题、颜色、字体、圆角、导航层级、题目/用户业务流程或移动 Sheet。
- 不新增 Dashboard 内容、首页营销内容、服务监控面板或 `/api/status` 替代接口。
- 不把“禁止页面 title/desc”扩大为删除业务对象名称、表单/区块标题、可访问名称或异常状态信息。
- 不修改 user-service、problem-service、submission-service、judging-service、judge-engine 或数据库。

## 待确认项

暂无。这里把用户所说的 title/desc 解释为“位于任务组件之前、只用于重复说明当前页面的通用介绍块”，
不包括题目名称、工作台版本名、表单/组件标题、登录与错误状态。首页删除介绍与状态后不新增替代内容；
本次意图审核将同时确认这一边界和统一 24px 间距。
