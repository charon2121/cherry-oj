# MEMORY-036：源码阅读问题与待验证的改进方向

## 背景

用户明确的问题不是单个文件太长，而是无法按“一条命令进来，到执行完毕”追踪源码；同时不知道硬编码数字的用途。
本记录保存需求来源，尚不包含已完成重构的经验。

## 决定与原因

本工作暂以等价重构为提案，架构边界待审见 DECISION-027。候选规范只在 DESIGN-043 维护，未经确认不进入全局规则。
保留当前 helper 是限定本次提案范围，不表示用户已认可其长期架构必要性。

## 尝试与教训

先前对话先从文件职责和维护性解释问题；用户进一步指出执行顺序、helper 的理由和数字含义，重构目标因此具体化。
仅拆文件、加常量或补架构说明不足以证明源码可读；最终判断要来自沿真实入口走通流程。
目前没有实施尝试，也没有“重构后已改善”的结论。

## 已知问题

WORK-048 在途代码尚需交接；数字依据可能缺失，必须记录未知而非编造；Linux 回归与阅读复核尚未执行。
旧有功能缺陷不与本次结构调整混改，清单见 VERIFY-050。

## 重新考虑条件

helper/执行器/目标平台变更；阅读复核显示现有分层仍难跟踪；等价要求与提案冲突；候选规则在实际代码中产生更多跳转或无意义包装。
发生时更新当前工作材料，不能先把未经验证的规则提升为全局约束。
