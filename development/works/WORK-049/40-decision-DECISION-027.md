# DECISION-027：阅读性重构与进程架构变更的边界

## 要决定什么

本工作是否在保留现有执行模型的前提下改善源码阅读路径，以及哪些规则仅作为未来规范候选。

## 背景

用户无法沿单条命令追到结束，也不理解 helper 额外增加的必要性和大量数字的含义。
现有 helper 隔离特权与 HTTP 处理；进程分离有收益，也引入协议和生命周期成本。
对现有方案提出疑问不等于授权移除进程或重新选择执行器。

## 候选方案

| 方案 | 收益 | 代价与范围 |
|---|---|---|
| 保留执行模型，重组主流程、交接、命名与数字表达 | 保持可比较基线，直接改善阅读问题 | 不能消除跨进程固有复杂度；属于本工作提案 |
| 合并 HTTP sandbox 与特权执行服务 | 减少一层本机交接 | 扩大 HTTP 进程权限范围，需独立权限方案及隔离验证 |
| 改用成熟隔离执行器或 rootless 路线 | 可减少自有启动代码或调整权限方案 | 需要能力探测、协议/资源/取消适配、部署与安全重新验证 |
| 只写导航文档、保持源码不动 | 改动小 | 不能解决隐含动作与魔法数字，不满足本次源码目标 |

## 决定

待人工确认的提案：采用第一种；本工作保留当前 helper 进程边界，不据此宣称该架构应永久保持。
重构方案的细节以 DESIGN-043 为准。未来编码规则仅保留候选，在实际重构和阅读验收后另行确认提升。
当前状态不代表人已经认可本提案，也不授权实施。

## 理由

用户本轮明确要求创建重构文档。先把阅读问题、等价边界和可验收目标讲清，避免把结构整理扩大成隔离架构重写。
保留行为基线可以区分阅读改进与功能/安全变化，并保护 WORK-048 的在途成果。

## 影响与风险

需要面对 helper/init/exec 的固有交接，不能通过注释宣称复杂度已经消失。
如果源码主线依然不可读，应重新设计编排与职责，而不是机械增加文档。
候选规范未经确认不得成为拦截未来工作的新增硬门禁。

## 重新考虑条件

用户明确要求重新评估 helper；发现等价重构无法达到 AC-001/AC-002；实现需要改变权限、协议或生命周期；
目标 Linux 能力或执行器选择变化。发生时先修订本工作定义和决策，架构变更可单独建立 WORK。
