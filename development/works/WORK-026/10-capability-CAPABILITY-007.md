# CAPABILITY-007：为 Java 服务提供可直接启动的本地默认配置

## 为什么需要

本地开发者当前必须记住并导出 judging-service 数据库密码，以及 user-service 的签名密钥标识、私钥
位置和公钥位置。缺少任何一项都会使对应服务启动失败。其它配置虽然也使用环境变量，但已拥有可用
默认值，或允许空值。项目需要一条统一规则，让 Java 服务在本地基础设施就绪后无需预设环境变量即可
启动，同时不降低生产 Secret 边界。

## 使用者

- 本地开发者：独立启动 Gateway、用户、题目、提交或判题服务进行开发和联调。
- CI 与维护者：验证默认配置完整，发现新增的强制环境变量。
- 部署运维：继续通过环境变量和 Secret 文件覆盖本地默认，不依赖仓库中的开发配置保护生产环境。

## 能力

- REQ-001：五个 Java 服务的每个本地启动必需环境变量都必须有可用默认；在基础设施已按项目约定准备
  好的前提下，启动命令本身不要求先 `export CHERRY_*`。
- REQ-002：环境变量覆盖名称、Spring 属性名称和覆盖优先级保持兼容；显式值总是优先于默认值。
- REQ-003：user-service 缺少显式密钥配置时只生成本地临时 RSA 密钥，不向仓库写入私钥；生产 profile
  必须拒绝临时密钥并要求稳定的 Secret 文件与明确 `kid`。
- REQ-004：数据库本地默认值在 user-service、problem-service 和 judging-service 间保持与本地账号
  约定一致；部署环境仍必须覆盖，日志和文档不得输出真实生产口令。
- REQ-005：Gateway 的空 Redis 密码、关闭的 exporter、judging 环境预置空字段以及 `${LOG_FILE}` 等
  Spring 运行时属性按语义保留，不能为了“非空”而填入错误值。
- REQ-006：自动化验证覆盖无 `CHERRY_*` 环境变量的配置绑定/应用上下文、显式覆盖和生产缺失 Secret
  失败，并扫描新增的无默认启动必需占位符。

## 接入方式

开发者继续从 `apps/server` 使用 `./mvnw -pl <service> spring-boot:run`。需要连接不同基础设施或模拟
部署时，仍可在命令前设置原有 `CHERRY_*` 变量；生产启动使用 production profile 与 Secret 注入。

## 输入与输出

输入是 Spring profile、可选环境变量以及本地基础设施。输出是解析完成的服务配置和可运行进程；临时
签名密钥只存在于 user-service 当前进程内，公开部分仍通过既有 JWKS 接口提供。

## 限制与失败

默认值不负责创建 schema、数据库用户、Redis 或判题引擎。基础设施不可达、数据库账号与默认口令不
匹配时，服务仍应保留原生且可定位的启动失败。production profile 缺少显式数据库凭据或签名密钥时
必须在启动阶段明确失败；不能退回临时密钥或本地口令。

## 质量要求

不新增网络调用或持久化密钥。随机 RSA 密钥只在本地 user-service 启动时生成一次。五服务聚合验证、
模块上下文测试和配置静态扫描必须通过；启动日志可以说明采用本地临时模式，但不得打印私钥或密码。

## 升级与迁移

原有显式环境变量无需迁移。已有开发者可删除手工 export 后使用默认值，也可继续保留个人覆盖。生产
部署在启用 production profile 前必须确认所有 Secret 已注入；回退时恢复原 application 配置即可。

## 不做什么

不自动安装或启动 MySQL/Redis/Go Judge，不创建数据库与用户，不修改 schema，不建立统一配置中心，
不提交开发私钥，不改变接口、端口或生产密钥轮换流程，也不把所有空字符串机械改成非空值。
