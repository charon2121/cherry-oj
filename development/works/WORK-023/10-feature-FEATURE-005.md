# FEATURE-005：设计双端导航栏与导航功能组件

## 为什么做

现有双端 Shell 已证明页面结构与权限边界可行，但导航仍只承载最少入口，账号动作也会随着角色和状态在
页头横向增长。继续直接追加链接会让桌面与移动端漂移、未交付能力提前曝光，并使管理菜单难以扩展。
本功能把导航的信息架构、身份动作和组件合同固定下来，让后续页面按同一规则接入。

## 使用者

- 访客：识别产品、访问当前公开页面并进入登录。
- 普通用户：访问已交付的答题相关入口，处理账号密码并安全退出。
- 管理员：在用户端与管理中心之间切换，通过分组侧栏进入管理页面并处理账号动作。
- Web 开发者：新增页面时复用导航模型和组件，不复制桌面/移动菜单或自行判断角色。

## 入口

- 所有非 `/admin/*` 页面自动使用用户端 Header 主导航与账号区域。
- `/admin/*` 在 ADMIN guard 通过后使用管理 Header 与侧栏导航。
- `/admin` 与 `/admin/dashborad` 继续进入同一个空 Dashboard；`/admin/users` 继续位于“账号管理”分组。

## 正常流程

```text
访客进入用户端 → 使用品牌/主导航 → 从账号区域进入登录
登录用户进入用户端 → 使用已交付主导航 → 从账号菜单改密或退出
ADMIN → 从账号菜单进入管理中心 → 在 Sidebar 选择 Dashboard 或展开业务分组
窄屏 → 从 Header 打开同一份导航 → 选择叶子后关闭面板并进入页面
```

## 业务规则

- REQ-001：保持 WORK-020/022 已确认结构：用户端为 Header/Main/Footer；管理端为 Header 与
  Main(Sidebar + Content)，不得恢复管理 Footer 或创建第二套全局壳层。
- REQ-002：用户端 Header 固定由品牌入口、主导航、账号区域组成。品牌始终返回 `/`；主导航只展示
  当前已交付且用户有权访问的页面，不显示禁用占位、`#` 链接或“敬请期待”。
- REQ-003：用户端导航模型按 MVP 预留“首页、题库、提交记录”的稳定顺序，但本工作只渲染已有路由
  “首页”；题库和提交记录必须在对应业务页面交付时才加入。
- REQ-004：访客账号区域只显示“登录”；Session 加载中显示明确状态，加载失败显示可操作重试，不能把
  查询失败当作未登录。
- REQ-005：登录用户使用统一账号菜单。触发器可识别用户名；菜单至少承载账号身份、修改密码和退出。
  ADMIN 额外看到“管理中心”；`passwordChangeRequired` 时，“请先修改密码”必须在不打开菜单时也能被
  感知，并在菜单中作为首要动作。
- REQ-006：退出沿用现有 Mutation 与 Session 缓存规则；退出中阻止重复提交，退出失败在账号区域提供
  `role="alert"` 的错误和重试能力，不因菜单关闭丢失错误含义。
- REQ-007：管理端 Header 只承载移动菜单触发器、Cherry OJ/管理中心标识、返回用户端和账号菜单；
  Dashboard、用户账号及未来管理业务入口都进入 Sidebar，不在 Header 重复。
- REQ-008：管理导航由可复用定义生成，支持“分组 → 一级项 → 二级叶子项”最多两级。当前固定为
  `Dashboard` 与“账号管理 → 用户账号”；有子项的项只负责展开，叶子项只负责导航。
- REQ-009：`/admin` 与 `/admin/dashborad` 同时激活 Dashboard；`/admin/users` 激活“用户账号”并自动展开
  “账号管理”。当前项使用 `aria-current="page"`，父级使用展开状态与文字结构表达归属。
- REQ-010：桌面用户端使用横向主导航，桌面管理端使用左侧 Sidebar。窄屏两端都通过带文字的菜单按钮
  打开 Sheet；移动菜单复用与桌面相同定义，选择叶子后关闭并由组件恢复焦点。
- REQ-011：页面级面包屑属于 Main 内容区的次级导航，不进入全局 Header。只有页面层级达到两层且有
  真实父页面时才显示；本工作定义接入边界，不为当前空 Dashboard 或首页制造面包屑。
- REQ-012：全局搜索、通知、主题、语言、帮助、收藏与快捷创建都属于未来扩展位。没有已交付功能、状态
  来源和目标页面时不渲染空按钮；未来增加时必须另建产品 WORK 并评估窄屏优先级。

## 边界与失败

- 320px 下品牌、导航触发器与账号触发器必须同时可用；关键状态不可只靠图标。
- 用户名过长时截断可见文本并保留完整可访问名称，不能撑出横向滚动。
- 无头像数据时使用用户名与 Lucide 用户图标，不伪造头像、首字母彩色头像或上传能力。
- 查询参数变化不应取消当前态；不同叶子路由不能因前缀匹配同时激活。
- 菜单组件异常不导致业务页面卸载，语义标签和叶子链接仍可理解。

## 要求

- REQ-013：优先复用项目现有 shadcn/ui Sidebar、Collapsible、Sheet、Button、Link；账号菜单优先采用当前
  `base-nova` 配置对应的 shadcn/ui Dropdown Menu 并覆盖为 Cherry OJ 设计合同。不得引入 Radix 第二套
  primitive。平面主导航保留语义 `nav + Link`，不为简单链接列表强加多级 Navigation Menu。
- REQ-014：所有样式只消费现有设计 token 与 Tailwind alias；不修改主题合同，不加入 raw 色值、`.dark`、
  theme id 分支或透明度捷径。
- REQ-015：两个登记主题使用相同 DOM anatomy、状态和控件优先级；不增加用户可见主题切换器。
- REQ-016：菜单支持键盘、Escape、可见焦点、焦点恢复和触控目标；纯图标控件必须有可访问名称，当前态
  和错误态不能只靠颜色。
- REQ-017：导航不发起新的业务 API；身份来自 Query Session，当前位置来自 Router，菜单开关使用组件
  内部状态，不引入全局状态库或持久化导航偏好。

## 验收标准

- AC-001：访客、USER、ADMIN 分别打开 `/`，均看到品牌、唯一主导航和正确账号区域；只“首页”为当前项，
  不出现题库、提交、搜索、通知或主题空入口。
- AC-002：USER 可用鼠标和键盘打开账号菜单，识别用户名，进入改密并退出；ADMIN 额外看到管理中心。
  首次改密、退出中和退出失败都有明确且可恢复的状态。
- AC-003：ADMIN 打开 `/admin`、`/admin/dashborad`、`/admin/users?page=1`，Header 与 Sidebar 职责不重复；
  前两个地址激活 Dashboard，用户页激活叶子并展开账号管理。
- AC-004：320px 下两端页头无横向溢出；Sheet 的项目顺序、权限和文案与桌面一致，选择叶子或 Escape
  关闭后恢复合理焦点。
- AC-005：键盘与辅助技术可识别导航名称、账号菜单、展开状态、当前页、错误与跳到 Main；200% 缩放、
  长用户名、reduced-motion、forced-colors 下仍可完成导航与退出。
- AC-006：Dropdown Menu、Sidebar、Collapsible、Sheet 均映射现有语义 token；两主题 anatomy 一致，源码
  门禁无 raw 值、主题分支、disabled opacity 或新 allowlist。
- AC-007：现有登录、改密、权限、Dashboard 双入口、用户管理和 Footer 行为不回退；不新增 API 请求、
  死链接、第三层菜单、管理 Footer 或未确认业务入口。

## 不做什么

- 不新增题库、提交、通知、搜索、设置、帮助、主题、语言或头像上传等业务页面与数据能力。
- 不修改 Session、角色、权限、退出协议、路由地址、Gateway API 或后端服务。
- 不设计三级菜单、可调整侧栏、折叠偏好持久化、命令面板或多管理员角色导航。
- 不修改用户 Footer，不恢复管理 Footer，不修改设计系统 token、主题或 manifest。

## 待确认项

无阻塞产品未知。默认采用“已交付才显示”的渐进导航；账号操作统一收进账号菜单；Main 内的面包屑只
定义接入规则，待真实层级页面交付时实现。
