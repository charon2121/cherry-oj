# MEMORY-040：会话期限需与持久化精度一致

## 背景

真实业务CI在首次登录后改密503。签发方直接返回纳秒期限，MySQL DATETIME(6)回读却是微秒，网关严格相等校验拒绝这一差异。

## 决定与原因

用户批准仅在签发源统一微秒精度；31b4019把同一截断值用于入库和返回。最多缩短999ns，不延长期限；不放宽网关校验，不改Schema或JWT/审计时间。

## 尝试与教训

整秒单测、数据库测试预截断输入及模拟身份服务未覆盖真实往返。ef3312e在MySQL实测.123456789变为.123457（+211ns），新精度测试失败；31b4019同测试全部通过，实际登录/改密/重登恢复。CI对必需8方法实行零skip和报告一致性核验。

## 已知问题

旧Redis纳秒期限会话不会自动修正，需正常重新登录；未部署现有用户环境。WORK-050的浏览器阶段仍失败，待TASK-112定位，93项完整基线尚未形成。准备阶段Testcontainers仅依赖正常stop/Ryuk，没有独立的逐容器零残留快照；业务栈清理已有实测证据。

## 重新考虑条件

更改数据库精度、会话时长类型或固定期限策略时重审此边界。其他生产缺陷另拆任务；本工作人工验收后交回WORK-050，WORK-049继续等待。
