# MEMORY-039：通过记录不能覆盖新观察到的中断

## 背景

WORK-050把手工验证接入CI，已多轮通过的内核事件等待路径随后出现EINTR，原日志不能区分Poll与Recvmsg。

## 决定与原因

用户已批准最小控制消息修复，实施先分阶段复现；不在测试中忽略或重跑整请求。

## 尝试与教训

真实失败与“预期拒绝”必须区分；不能把启动事件尚未收到的系统调用错误当作已完成权限/握手验证。

## 已知问题

ReceiveEvent直接返回EINTR，具体信号来源和FD/期限恢复语义尚待确定性验证；没有已实施修复。

## 重新考虑条件

最小用例证伪候选、发生FD重复/泄漏或期限延长时回到设计，不扩大循环重试。
