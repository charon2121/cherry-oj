# EXPERIENCE-008：设计 Cherry OJ 任务入口主页

## 体验类型

面向答题用户的产品入口体验，同时为产品负责人和后续 Web 开发者提供可执行的视觉目标。主页不承担
营销转化或数据分析，而是帮助用户以最少判断进入下一项任务。

## 入口与主流程

### 桌面主流程

1. 232px 退后侧栏呈现 Cherry OJ、首页、题库和我的提交；当前项有文字与位置识别，不只靠品牌色。
2. 主区顶部 64px location bar 只显示当前位置和账号动作，不放尚未确认的全局搜索或主题切换器。
3. 紧凑 Hero 使用 `Cherry OJ · C++ ACM`、标题“从读题到判题结果，专注完成每一次提交”和说明：
   “浏览公开题目，编写并自测 C++，提交后清楚查看排队、判题与最终结果。”
4. 匿名用户看到“浏览题库 / 登录”；普通用户看到“浏览题库 / 我的提交”；首次改密用户优先看到
   warning 和“修改密码”。
5. Hero 右侧或下方用一个普通 Panel 说明四步答题路径；其后用带分隔线的紧凑入口行提供题库、我的
   提交和按角色出现的管理入口，不堆叠大 Card。
6. 页面末尾用小型 Inline Notice 表达 Gateway 连通性；它是辅助事实，不是产品主卖点。

### 320px 主流程

侧栏收敛为顶部品牌与可展开/可横向浏览的导航，正文按“介绍 → 操作 → 四步路径 → 快速入口 → 状态”
单列排列。主要按钮可占满可用宽度，入口行改为上下文清楚的列表，不缩成难点按的图标阵列。

## 异常状态

- Session 检查中：账号区域显示“正在检查登录状态…”，公共内容保持稳定，不先闪出登录再替换。
- Session 查询失败：显示就地“登录状态加载失败，重试”；不清空公共入口、不假定用户已退出。
- 匿名：允许访问公开题库；“我的提交”和管理入口不出现，登录保留安全回跳。
- 首次改密：warning 在主要内容之前，主 CTA 为“修改密码”；受保护入口显示不可用原因。
- ADMIN：在普通用户导航之后新增管理分组，不改变 Hero 与答题入口。
- Gateway 不可用：底部状态改为 danger/info notice 和“重试”，不展示内部堆栈或把它写成用户 WA。
- 题库或提交为空/加载/错误属于后续页面，本主页不虚构其数据卡片。

## 交互与文案

- Eyebrow：`Cherry OJ · C++ ACM`。
- 标题：`从读题到判题结果，专注完成每一次提交`。
- 说明：`浏览公开题目，编写并自测 C++，提交后清楚查看排队、判题与最终结果。`
- 四步：`选择题目`、`编写与自测`、`正式提交`、`查看结果`。
- 快速入口：`题库 / 浏览已发布题目`、`我的提交 / 回看排队、判题与最终结果`；管理员按角色增加
  `管理 / 维护题目、用户与提交`，不得向普通用户展示。
- 按钮使用明确动词，不写“立即体验”“探索无限可能”等营销口号。
- 系统状态只写 `Gateway 已连接` 或 `服务暂时不可用`；不写“全部服务健康”。

## 可访问性

- 阅读与 Tab 顺序与视觉顺序一致；跳过链接可直接到主内容，当前导航使用 `aria-current` 意图注释。
- 焦点是 2px 实线加 2px offset；普通文字 ≥4.5:1，必要边界/图标/focus ≥3:1。
- 导航、warning 和状态除颜色外都有文字、图标或位置编码；Cherry 品牌色不代替 danger。
- 320px、200% 缩放与长中文下不裁切核心信息和操作；触控目标至少按项目控件尺寸呈现。
- reduced-motion 下不依赖位移或平滑滚动理解状态；本稿不加入无必要动画。

## 调试与恢复

Figma 图层按 `Page / Section / Component / State` 命名，Frame 和局部组件返回稳定 node id。问题先按
主题 mode → semantic variable → component variant → page composition 四层定位；每完成一个区块就
截图检查裁切、重叠、占位文案和字体。若目标态需要新增产品能力，停止画布扩张并回到 FEATURE-002；
若仅是布局问题，按 node id 做局部修复。Figma 失败不影响当前 Web，回退方式是删除本任务新建 Draft。
