# FEATURE-002：设计 Cherry OJ 任务入口主页

## 为什么做

当前首页主要展示前端骨架和 Gateway 连通性，适合开发联调，不足以承担产品入口。主页需要把 Cherry OJ
当前可确认的核心任务——浏览公开题目、完成 C++ ACM 答题、查看提交状态与结果——组织成一条清楚、
克制且可响应的入口体验，并为不同登录状态保留可恢复路径。

## 使用者

- 未登录访客：可以先理解平台当前能做什么并进入公开题库，需要受保护能力时再登录。
- 普通用户：进入平台后快速前往题库或“我的提交”，理解一次完整答题会经历哪些阶段。
- 首次登录且必须改密的用户：优先完成密码修改，不误以为受保护功能已经可用。
- 管理员：仍以答题入口为主，在角色允许时看到次要的管理入口。

## 入口

所有人访问根路径 `/`。页面根据已有 Session 状态调整动作，但公共内容与结构保持稳定；登录后安全
返回原目标。Figma 交付表达的是目标态信息架构，不代表当前仓库已经实现题库和提交路由。

## 正常流程

```text
访问首页
  → 看到 Cherry OJ 当前 C++ ACM 定位与四步答题路径
  → 匿名用户：浏览公开题库，或登录后返回目标
  → 普通用户：浏览题库，或进入“我的提交”
  → 首次改密用户：先修改密码，再进入受保护能力
  → 管理员：在普通入口之外看到次要管理入口
```

## 业务规则

- REQ-001：主页是应用内任务入口，不是营销长页、组件画廊、个人统计看板或开发状态面板。
- REQ-002：普通答题用户是主角色，信息与文案只承诺当前 MVP 的 C++ ACM 答题闭环。
- REQ-003：首屏必须提供一个主要动作“浏览题库”；匿名次要动作是“登录”，已登录普通用户次要动作是
  “我的提交”。MVP 不提供注册入口。
- REQ-004：主页用紧凑结构说明“选择题目 → 编写与自测 → 正式提交 → 查看结果”四步，不把每一步做成
  大面积彩色 Card。
- REQ-005：桌面应用壳包含品牌、首页、题库和我的提交；ADMIN 管理入口按角色增加且不抢占普通主流程。
- REQ-006：首次登录需改密时显示置顶 warning，主要动作改为“修改密码”，受保护入口明确不可用。
- REQ-007：Session 检查中或查询失败时保留公共内容和稳定骨架；失败提供就地重试，不伪装为已退出。
- REQ-008：Gateway 连通性只作为页面底部或辅助区的小型状态，不能写成“整个系统全部正常”。
- REQ-009：Figma 稿中出现的题库、提交和管理入口必须标注为“目标态”，不得表示当前路由/API 已完成。
- REQ-010：本功能只产出 Figma 设计和 WORK-019 记录，不修改 Web 实现、设计系统真源或产品契约。

## 边界与失败

- 没有登录态时，公开题库入口仍可见；受保护入口引导登录并保留安全回跳。
- Session 查询失败只影响身份相关动作，公共介绍和答题路径继续可读，并提供“重试登录状态”。
- 首次改密状态不得让“我的提交”和管理入口看起来可操作。
- 服务状态失败使用“服务暂时不可用，可重试”，不泄漏内部服务、请求体、凭证或调试细节。
- 本设计不展示真实用户、提交、隐藏测例或标准答案；示例文字必须是合成内容。

## 要求

- REQ-011：只使用 `docs/design-system.md` 允许的 semantic token、字体、4px 间距节奏、6/8/12px 圆角
  与 150/200ms 动效；不引入 raw 主题分支或第二套视觉语言。
- REQ-012：默认 `cherry-black` 与 `pure-white` 保持相同 anatomy、尺寸、状态和阅读顺序。
- REQ-013：提供 1440px 桌面与 320px 窄屏稿；窄屏不裁切主要动作、状态或长中文。
- REQ-014：普通文字对比至少 4.5:1，必要边界、图标和 focus 至少 3:1；焦点使用可见 2px outline 与
  offset，交互顺序可由键盘理解。
- REQ-015：颜色不是唯一信息来源；warning、服务状态和未来 verdict 位置都同时使用文字与稳定图标/
  结构。品牌 Cherry 色不承担 destructive 含义。
- REQ-016：Figma 结构必须可编辑并组件化；重复导航项、按钮、步骤项和入口行使用组件或实例，颜色和
  间距绑定变量，不交付一棵扁平的一次性图层树。

## 验收标准

- AC-001（普通用户桌面）：在 1440px `cherry-black` Frame 中，用户能在首屏理解产品定位，并找到
  “浏览题库”和“我的提交”；四步答题路径与辅助状态清楚但不抢主操作。
- AC-002（匿名桌面）：同一结构切换为匿名状态后，公共题库仍可进入，次要动作变为“登录”，页面不出现
  注册、我的提交数据或管理员入口。
- AC-003（首次改密）：切换到 `passwordChangeRequired` 注释状态后，warning 与“修改密码”成为优先
  路径，受保护入口不会被误读为可用。
- AC-004（窄屏）：在 320px Frame 中按“品牌/导航 → 介绍 → 主操作 → 四步路径 → 快速入口 → 状态”
  顺序阅读，无横向裁切，按钮和长中文仍可用。
- AC-005（主题）：普通用户桌面稿绑定 `pure-white` semantic collection 后保持相同结构，文字、边界、
  品牌操作和焦点符合各自主题合同，没有从暗色直接搬用不可读亮粉。受 Starter plan 限制并经用户批准，
  两套主题用独立单 mode collection 表达，不要求同一 collection 内切换 mode。
- AC-006（结构）：Figma metadata 显示 semantic variables、局部组件和实例关系；所有完成区块已去除
  placeholder，文本字体家族经读回确认为 Inter/中文系统回退意图。
- AC-007（范围）：设计中没有注册、排行榜、竞赛、课程、讨论、AI 宣传、多语言、主题切换器、虚构
  个人统计或 WA 隐藏测试点详情；仓库实现文件无改动。

## 不做什么

- 不设计题库列表、题目详情、编辑器、提交详情或管理页面本身。
- 不实现 Web、不新增路由/API、不改设计系统 token/组件合同。
- 不提供注册、找回密码、社交登录、排行榜、竞赛、课程、讨论、收藏、连续打卡或个人能力统计。
- 不宣传 AI 出题，不展示 Python/Java 等当前首切片未承诺语言。
- 不提供主题切换入口；双主题稿只用于设计合同校验。
- 不固定展示 A+B、真实最近提交或通过率；A+B 只是 WORK-002 的验收题，不是主页永久内容。
