# IMPROVEMENT-004：Linux 沙箱隔离与资源计量硬化

## 当前问题

当前能运行和判题，但用户程序仍可能访问运行机器的文件、网络和其他进程。资源统计也会受此前任务影响。需要让每份代码在独立、受限的环境中执行，并在结束后彻底清理，才能在提供的 Ubuntu 服务器上可靠运行沙箱服务。

## 当前数据

WORK-044/047：大输出后空程序被误判 MLE，峰值 281927680 bytes；死循环配置 CPU 1 秒但约 10 秒墙钟结束。当前 hostContainer 使用工作目录、os/exec、进程组 kill、wait4 Maxrss，没有 namespace/cgroup。现有 Docker 容器隔离服务进程，不等于逐任务隔离。

## 目标指标

- REQ-001：每次编译与运行独立隔离文件、进程、网络和权限，不可读取宿主秘密或干扰其他任务。
- REQ-002：CPU 与内存覆盖全部子进程，逐次计量，消除历史执行对后续任务的峰值污染；CPU 总预算与墙钟期限分开限制。
- REQ-003：限制进程数、工作目录、输入输出和整个节点的总资源；取消、崩溃、超时后终止所有后代并回收资源。
- REQ-004：Ubuntu 使用可复现配置与受控权限运行，启动时核验必要能力；隔离不可用必须拒绝服务，不自动回退 host。
- REQ-005：保持 sandbox 只执行命令的职责，正式提交和自定义运行共用硬化后端，升级后重新注册与校准。

## 影响范围

Go sandbox/container、资源控制、runner、pool、配置与启动入口，Ubuntu 部署材料和 Linux 测试。首轮保障当前 C++ ACM 编译与执行，不增加新语言、比赛或 Web 页面。协议字段确需变更时先补契约设计，不直接扩大实现。

## 主要风险

共享 Linux 内核仍有内核漏洞风险；隔离不能代替内核更新和最小化宿主。权限/helper、文件句柄与挂载、进程启动竞态、编译器兼容性为重点复核对象。首站只读能力已记录，实际隔离行为仍待验证。

## 验证方式

- AC-001：宿主文件、其他任务、外网、宿主进程、提权及挂载访问测试被拒绝；正常编译与动态链接程序可执行。
- AC-002：单进程与多子进程 CPU 累计受限；内存触碰/OOM、编译资源独立计量；先大输出再空程序不产生历史 MLE。
- AC-003：fork/线程扩张、后台后代、setsid、取消及服务崩溃场景完成清理；连续 1000 次执行后无残留任务进程、挂载或 cgroup，文件增长有界。
- AC-004：目标 Ubuntu 能力检查、systemd 服务停止/崩溃后的受控恢复、配置缺失拒绝启动、节点级资源压力验证通过，部署与回退可复现。机器重启恢复按用户 2026-09-10 决定移出本轮验收，留置 TASK-108 方案后续承接，不计为已验证。
- AC-005：真实自定义运行 stdout/stderr、CE/RE/TLE/MLE/OLE 和正式提交 AC/WA 通过；记录测量单位、口径、误差和性能基线。

## 持续观察

记录任务清理失败、OOM/进程上限事件、CPU 超限误差、可用槽位及控制进程资源。异常节点停止接收任务；不在日志记录代码、测试数据和凭据。
