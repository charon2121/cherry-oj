# PLAN-032：Linux 沙箱隔离与资源计量硬化

## 目标

交付具备真实 Linux 隔离、计量、回收和 Ubuntu 部署证据的 C++ 编译/运行后端。

## 改动区域

Go sandbox、cgroup、配置、启动命令、Linux 测试及 deploy/sandbox-linux；不修改 Web、Java 业务或数据库。首个 TASK 只做探测与接口设计，后续细分任务由探测结果生成，避免提前授权未知的特权实现。

## 阶段与顺序

1. TASK-093：服务器/本地 Linux 能力探测，固定架构、控制器、权限、helper 启动机制与系统调用支持矩阵。
2. 基础设施：cgroup 生命周期与计量、无竞态入组、namespace/rootfs/权限/helper；编译和执行策略同时覆盖。
3. 接线：runner 状态与预算、文件安全、进程回收、节点级限额和启动自检。
4. 验证：隔离攻击面、资源压力、1000 次回收、故障注入与独立复核。
5. Ubuntu 交付：经审核安装，注册新环境、部署数据、重新校准，真实自定义运行及正式提交回归。

## 并行与依赖

隔离与资源控制接口先统一，再拆成独立任务；不能先让用户程序启动再补隔离。首站服务器已提供且确认为项目专用；只读盘点不记为 Ubuntu 交付完成。

## 迁移与交付

所有配置示例与服务定义版本化，私有值不进 Git。提供启动/停止/健康检查/卸载命令，记录二进制、rootfs、策略摘要及内核能力。服务器信息补齐后先列只读探测结果，不修改不相关服务或全局安全配置。

## 风险

新节点切换期间旧题目可能未校准，先在独立节点准备后安排切换。禁止在未知共享宿主上运行 fork/OOM 等压力测试。

TASK-100 实查现有管理入口仅向 ACTIVE 部署/校准，已发布版本也不能原地校准。具体顺序调整为
准备复用原数据的新草稿、审批具体环境切换、部署、独立校准、发布及真实业务测试；详见TASK-100切换清单。
切换至校准完成之间存在业务不可用窗口；新修订发布后不能只切回旧环境就视为业务恢复。

## 验证

逐项对应 IMPROVEMENT-004 AC-001～005。Mac 单测、Docker VM 中的 Linux 测试和目标 Ubuntu 实测分开记录；跳过项不能算通过。

## 回退

停止接收任务、终止本服务任务组、清理挂载后切回上一个已硬化镜像/策略和对应已校准环境；保留版本化配置与数据。尚无已硬化版本时回退为停止对不可信代码提供服务，不能回退到 host 并继续对外运行。

## 跨 Linux 分阶段验证

- 第一批：用户 Ubuntu 24.04.4 / 6.8.0-124-generic / x86_64 专用测试服务器，保留系统及云厂商代理，建立功能/安全/资源基线。
- 第二批：可提供的 Ubuntu 其他版本、Debian、RHEL 兼容环境，分别记录默认与云厂商内核、LSM策略，不直接关掉系统安全机制。
- 架构覆盖：x86_64、arm64 分别执行实际隔离测试；仅交叉编译不算运行通过。其他架构先记录不支持，按实际需要扩展。
- 每台机器执行统一的能力探测、C++ 编译运行、隔离攻击面、CPU/内存/进程上限、取消/崩溃回收、大输出后小程序回归、节点身份和正式提交验收。
- 测量与压力测试在经确认的专用测试机上进行，记录输入预算、机器资源、并发和观测结果。外层 Docker 不能替代宿主/虚拟机目标矩阵。
- 支持矩阵随每轮报告更新；没有测试的组合保持待验证，缺能力组合保留拒绝启动结果。常规 CI 不具备相应权限时只跑编译/单测，真实隔离测试单独安排受控 Linux runner。
