# FEATURE-007：交付题库、题目与测试数据管理

## 为什么做

Cherry OJ 已有应用外壳和身份能力，但学习者还看不到真实题目，管理员也无法安全地把题面、样例、
隐藏测试数据和判题限制准备成一个可发布版本。本功能把题目生产的最小人工流水线与公开题库一起做完，
为后续编辑、自测和正式提交提供真实、不可变、可追溯的题目输入。

## 使用者

未登录访客和已登录学习者浏览公开题库。ADMIN 负责创建与修订题目、维护样例/语言、上传隐藏测试数据、
部署数据、填写绝对限制、运行发布前验证并显式发布。首版管理流程只创建 C++ ACM 题目。

## 入口

用户端主导航新增“题库”，进入 `/problems`，详情为 `/problems/{slug}`。管理端导航新增“题目管理”，
进入 `/admin/problems`；新建、编辑、测试数据和发布检查都在稳定的题目/版本地址下完成。

## 正常流程

```text
打开题库
  → 查看最新公开题目
  → 可选：输入关键字或选择难度、标签、代码模式、语言
  → 打开一道题
  → 阅读题面、输入输出说明、约束、提示和样例
  → 查看当前允许语言及起始代码信息
  → 返回题库时保留可分享的筛选条件

管理员进入题目管理
  → 创建 Problem 和第一个 C++ ACM 草稿版本
  → 编辑题面、样例、C++ starterCode 与版本说明
  → 上传成对 .in/.out 测试数据包并查看 manifest/hash
  → 绑定测试数据并部署到当前判题环境
  → 填写绝对 CPU/时钟/内存限制
  → 提供临时参考程序运行发布前验证
  → 预览公开详情并显式发布
  → 后续修改从已发布版本创建新草稿，不原地覆盖
```

## 业务规则

- REQ-001：题库列表只包含 `ACTIVE + PUBLIC` 且存在当前 `PUBLISHED` 版本的 Problem；默认按更新时间
  倒序并以题目 id 稳定打破同一时间的排序。
- REQ-002：列表项公开 `problemId、slug、currentVersionId、versionNo、title、difficulty、tags、
  codeMode、allowedLanguages`，详情在此基础上公开当前版本题面、输入输出说明、可选约束/提示、按顺序
  排列的样例，以及每门允许语言的 `starterCode`。
- REQ-003：详情按稳定 `slug` 访问；不存在、私有、归档、无当前发布版本或当前版本不可发布的题目均
  对普通调用者表现为同一种 404，不暴露记录是否存在。
- REQ-004：关键字匹配标题或 slug；支持难度、单个标签、代码模式和语言筛选，以及更新时间正序/
  倒序。空白输入等同未筛选，非法枚举、超长输入或失效游标明确拒绝。
- REQ-005：列表使用不透明游标分页，每页默认 20、最多 100；游标只对创建它的筛选与排序组合有效，
  客户端不得解析或拼装。
- REQ-006：新版本发布后，后续读取可以看到新的当前版本；已经公开的历史版本不提供普通用户读取入口，
  也不改变未来 Submission 对旧版本的追溯语义。
- REQ-007：筛选、排序、页大小与当前游标保存在类型安全的 URL search params；改变任一筛选条件时清空
  旧游标，浏览器前进、后退和刷新保持一致结果位置。

## 边界与失败

首次加载显示骨架或可读加载状态；无公开题目和筛选无匹配使用不同空状态；网络或服务错误保留当前
筛选并提供重试；失效游标提示回到第一批结果；详情 404 提供返回题库入口。匿名浏览不应被登录页拦截，
已登录但需要修改密码的用户仍可读取同一公开内容。

## 要求

- REQ-008：浏览器只访问 Gateway 的 `/api/problems`；problem-service 的公开读模型不得序列化
  `judgeTemplate、testDataVersionId、storageRef、manifest、contentSha256、createdBy、publishedBy`
  或审计详情，也不得把私有/草稿是否存在写进错误差异。
- REQ-009：题面 Markdown 使用项目既定的 `react-markdown + remark-gfm + rehype-sanitize` 路径，默认
  不执行原始 HTML；标题层级、表单标签、键盘焦点和窄屏阅读必须可用，难度与代码模式不能只靠颜色。
- REQ-010：生产 migration 只创建设计文档已经确认的 problem-service 表，不夹带业务题目；A+B 演示题
  只能由显式开发 profile seed 创建，并且重复启动幂等。
- REQ-011：查询输入有长度和数量上限，服务端只读取 `size + 1` 行判断 `hasMore`，不为公开题库执行
  全量 `COUNT(*)`；必须记录有界的结果数、耗时和错误分类，不记录题面正文或游标内容。
- REQ-012：Gateway 继续生成公开 request ID，并使响应 header 与 `meta.requestId` 一致；下游超时、不可用
  和契约错误不得伪装成空列表或题目不存在。
- REQ-013：所有 `/api/admin/problems/**` 读取和写入都要求有效 ADMIN Session；写操作同时要求 CSRF。
  USER、匿名和 `passwordChangeRequired` 主体不得读取草稿、测试数据、限制或发布检查。
- REQ-014：ADMIN 能分页查看 Problem、当前状态、当前公开版本和草稿版本；能创建全局唯一 slug 的
  Problem 与初始 `DRAFT` 版本。首版新建只接受 `codeMode=ACM`、`languageId=cpp`。
- REQ-015：未发布版本可以编辑标题、Markdown 各章节、难度、标签、样例、C++ starterCode、修改说明
  和绑定的测试数据版本；每次更新携带 rowVersion，过期编辑返回冲突且不静默覆盖。
- REQ-016：样例作为有序整体保存，ordinal 从 1 连续；草稿预览复用公开渲染组件但从 ADMIN API 读取，
  预览地址和响应不得被普通用户访问或缓存。
- REQ-017：ADMIN 可删除尚未发布、未被引用的草稿版本；已发布/归档版本、READY 测试数据以及仍被版本
  引用的记录不得物理删除。Problem 归档后从公开题库消失，但历史版本和审计保留。
- REQ-018：测试数据以 ZIP 上传，根目录只允许成对的 `<case>.in`/`<case>.out` 普通 UTF-8 文本文件；
  禁止目录、软链接、重复名、路径穿越、空 case 名、孤儿文件、NUL 和超出配置的文件数/压缩/解压大小。
- REQ-019：上传先产生 `UPLOADING` TestDataVersion，流式校验并计算包 hash、每文件 hash、caseCount、
  totalBytes 和 manifest；全部成功后原子封存为 `READY`，失败为 `FAILED` 并清理临时资产。READY 内容不可
  覆盖，再上传永远产生新 id。
- REQ-020：ADMIN 能查看同题测试数据版本及状态/manifest/hash，下载原始不可变包，并把 READY 版本绑定
  到本题草稿；普通用户接口、日志、错误和审计不得出现测试内容、标准答案、storageRef 或下载地址。
- REQ-021：ADMIN 可请求把绑定数据部署到当前唯一 ACTIVE 判题环境；重复请求按
  `testDataVersionId + environmentId + expectedSha256` 幂等。judging-service 在临时目录重新校验 hash/
  manifest 后原子切换 `<testdataRoot>/<testDataVersionId>`，只在成功后记录 READY 回执。
- REQ-022：ADMIN 为草稿的 C++/当前环境填写正整数绝对 `cpuNs、memoryBytes` 和可选 `clockNs`。限制只有
  在绑定数据已部署、参考程序以全部隐藏数据得到 AC 后才能成为当前 VALID calibration；参考源码只用于
  本次验证，不写业务表、日志或审计正文。
- REQ-023：草稿依次经过 `DRAFT → VALIDATING → READY_FOR_REVIEW → PUBLISHED`。任何本库校验、数据
  部署、参考程序或 readiness 失败都回到可编辑状态并显示具体安全原因，不改变公开当前版本。
- REQ-024：发布前必须确认题面/样例/语言/模板规则、READY 测试数据、当前环境 READY deployment 和
  VALID calibration；远程检查完成后，problem-service 在一个本地事务内锁定 Problem/版本，写
  PUBLISHED、切换 currentPublishedVersionId 并记录审计。并发发布只能有一个确定结果。
- REQ-025：PUBLISHED 版本及其样例、语言、数据绑定不可修改。创建修订时从当前版本复制可公开内容到
  新 DRAFT、分配递增 versionNo；测试数据是否复用必须由管理员显式确认。
- REQ-026：管理端所有写操作具有重复提交边界；网络失败后重新读取服务端状态，不凭页面提示推断成功。
  审计记录创建、更新、删除草稿、上传/绑定/部署数据、验证、发布和归档，但只保存允许字段摘要。
- REQ-027：测试数据上传/下载/部署全程流式处理，不把完整包读入 JVM 内存；临时文件有唯一目录、权限
  0600/0700、成功/失败清理和启动时有界恢复。外部 HTTP、文件传输和 Go judge 调用均不进入数据库事务。
- REQ-028：管理表单提供字段级错误、未保存/保存中/冲突/验证中/发布中状态；危险删除/归档/发布使用
  明确动词和确认，键盘、长 Markdown、代码、窄屏和失败恢复遵守设计系统。

## 验收标准

- AC-001（匿名列表）：未登录访问 `/problems`，能看到开发 profile 中的公开 A+B；响应与页面列出标题、
  难度、标签、模式和 C++，且不创建登录 Session 依赖。
- AC-002（筛选与分页）：准备超过一页且含不同难度/标签/模式/语言的数据，组合筛选只返回匹配项；继续
  浏览无重复或遗漏，修改筛选后从第一批开始，刷新和前进后退保持 URL 状态。
- AC-003（详情）：从列表打开 A+B，题面、输入输出、样例和 C++ starterCode 顺序正确；复制详情地址在
  新匿名窗口可直接打开。
- AC-004（不可见数据）：私有题、归档题、草稿、旧版本和不存在 slug 均不出现在列表，详情统一 404；
  列表、详情、错误、日志和浏览器状态中都找不到隐藏数据及 `judgeTemplate` canary。
- AC-005（失败恢复）：problem-service 超时或返回非法响应时页面显示可重试错误，不展示空列表；失效
  cursor 可以回到第一页，已有筛选不丢失。
- AC-006（可访问性与窄屏）：仅用键盘可完成进入题库、修改筛选、打开详情和返回；320px 下无关键内容
  或操作裁切，状态包含可读文字，题面标题结构可被辅助技术理解。
- AC-007（数据落地）：空 MySQL 8.4 实例能执行 V1 migration，约束和索引与
  `docs/database-design.md` 一致；生产 profile 无题目，开发 seed 重复执行不产生重复记录。
- AC-008（创建与预览）：ADMIN 创建 C++ ACM A+B 草稿，编辑题面、两组样例、标签和 starterCode；刷新
  后内容与 rowVersion 正确，公开题库仍不可见，ADMIN 预览与最终公开布局一致。
- AC-009（测试数据）：上传含 `1.in/1.out/2.in/2.out` 的合法 ZIP 后得到 READY、hash 和四文件 manifest，
  可下载同一包并绑定草稿；路径穿越、孤儿文件、重复名、超限和损坏 ZIP 均失败且无 READY/残留资产。
- AC-010（部署与验证）：绑定数据部署到当前环境，重复部署不产生第二份事实；填写绝对限制并以正确
  参考程序验证得到 VALID，以错误程序验证失败且不覆盖上一有效事实。
- AC-011（发布）：全部条件满足后显式发布，公开题库立即出现 A+B；发布请求超时后重试只产生一个
  PUBLISHED 版本和一个当前指针，审计可追溯，测试内容仍不可见。
- AC-012（不可变修订）：编辑已发布版本被拒绝；从它创建 v2 草稿、修改标题并发布后新访问看到 v2，
  v1 保持原内容且不可修改。
- AC-013（管理权限与并发）：匿名/USER 无法访问任何管理、下载或部署接口；两个管理员窗口用同一旧
  rowVersion 保存时只有一个成功，另一个看到冲突并可重新加载。
- AC-014（跨服务失败）：资产存储、judging-service 或 Go judge 暂时失败时草稿和已发布当前指针保持
  不变，页面能按 request ID 重试；恢复后从服务端实际状态继续，不重复上传/部署/发布。

## 不做什么

CORE 题目创建/模板验证、多语言管理、自动生成器/oracle/差分测试、对象存储供应商、判题环境注册与切换
页面、自动标定、做题编辑器、自定义测试、正式提交、用户 solveStatus、收藏、排行、竞赛、课程、讨论、
复杂搜索相关性和搜索服务都不在本工作。公开读模型仍能安全展示数据库中未来存在的 CORE/多语言题目。
