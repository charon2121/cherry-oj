# EXPERIENCE-013：交付题库、题目与测试数据管理

## 体验类型

同时覆盖访客/学习者的公开浏览体验和 ADMIN 的题目生产工作台。视觉与交互遵守已确认的 Cherry OJ
双主题设计系统，不新增 token、主题或组件合同。

## 入口与主流程

“题库”进入站点桌面和移动主导航，位置紧邻首页。列表页先显示标题、简短说明和筛选区，再显示结果
数量语义（“当前已加载 N 道”，不虚构总数）与题目列表。每项以标题作为主要链接，slug/难度/标签/
模式/语言为辅助信息；继续加载使用明确按钮，不在用户接近页面底部时自动请求。

筛选表单包含关键字、难度、标签、代码模式、语言和排序。提交筛选或清空条件后回到首批结果；选择项
直接映射 URL，返回列表时恢复。详情页顶部提供返回题库的链接和版本元信息，正文依次为题目描述、输入、
输出、约束、样例、提示与允许语言；缺失的可选章节不渲染空标题。

管理端“题目管理”先展示题目、当前公开版本、草稿状态和最近更新时间。创建后进入版本工作台，按
“基本信息—题面与样例—C++—测试数据—部署与限制—预览发布”组织为可直接定位的章节，不把长表单塞进
多层弹窗。每一节独立显示保存状态和 rowVersion 冲突；顶部始终显示当前 Problem、版本号和生命周期。

测试数据区支持拖放或文件选择 ZIP，上传前显示格式与当前限额，上传中显示字节进度和可取消状态；
完成后只展示 case 名、文件大小/hash、总量和状态，不把隐藏输入/输出直接铺在页面。管理员可以显式
下载原包核对、绑定版本、部署、重试失败部署。发布区以检查清单展示本地字段、数据 READY、环境部署、
参考程序和有效限制；缺项直接链接回对应章节，全部通过后才启用“发布此版本”。

## 异常状态

- 初次加载：列表结构保持稳定，显示“正在加载题目”；筛选控件仍可阅读但避免重复提交。
- 全局为空：说明“题库暂时还没有公开题目”，不暗示用户筛选错误。
- 筛选为空：展示当前条件和“清空筛选”，不把它当网络失败。
- 加载下一批失败：保留已加载内容，在列表尾显示重试，不清空第一页。
- 首次请求失败：显示 request ID（若可用）、重试和返回首页；服务失败不能显示“暂无题目”。
- 详情不存在：显示“题目不存在或暂未公开”，只提供返回题库，不区分私有、归档和真实不存在。
- cursor 失效：保留筛选，提示结果位置已过期并回到第一批。
- 草稿保存冲突：保留本地输入，显示服务端已变化并提供重新加载；不自动覆盖或无提示合并。
- 上传失败：显示稳定原因和 request ID；损坏/超限包不得显示为可绑定，允许选择新文件创建新版本。
- 部署/验证失败：保留 READY 源数据和草稿，展示安全摘要与重试；不回退已存在的有效公开版本。
- 发布检查失败：按检查项标出缺失条件；发布请求结果不明时先刷新版本状态，不能直接再建版本。
- 存储或 judging-service 故障：页面区分“资产暂不可用”“环境未就绪”和“参考程序未通过”，不统称
  保存失败。

## 交互与文案

筛选状态以表单值和 URL 为唯一可恢复来源；不在 Effect 中另存一份派生状态。题目链接使用真实链接，
支持新标签页。难度显示中文名称并保留稳定 code 的可读映射；ACM/CORE 同时显示完整名称，标签不是
可点击按钮时不伪装成交互。分页按钮在请求中保持尺寸并显示加载文案，失败后恢复可操作状态。

管理表单使用明确“保存草稿”“上传新测试数据版本”“部署到当前环境”“验证参考程序”“发布此版本”
动词。发布、归档和删除草稿需要确认对话框并说明不可逆边界；普通保存不弹成功对话框。测试数据 hash
提供复制按钮但不把 storageRef 暴露。参考源码编辑框明确“仅本次验证，不保存”，离开前清空。

## 可访问性

筛选项具有关联 label，错误与控件通过可访问描述关联；结果更新使用克制的 live region，避免每次输入
都打断读屏。主标题只有一个一级标题，Markdown 从二级标题语义继续，不让用户题面原始一级标题破坏
页面结构。焦点在导航、筛选、题目链接、继续加载和返回入口均清晰可见。320px 下筛选纵向排列，长标题、
长标签和代码块允许换行或横向滚动，不裁掉正文和返回入口。

管理工作台所有章节能用跳转链接和键盘抵达；上传区同时保留原生 file input，拖放不是唯一入口。进度、
READY/FAILED、部署和发布检查都用文字/图标而非只靠颜色。表格在窄屏转换为有标签的列表或提供可用
横向滚动；代码/Markdown 编辑区不拦截浏览器必要快捷键，错误摘要与字段关联。

## 调试与恢复

页面错误优先展示稳定、脱敏的用户文案；request ID 作为支持定位信息。开发环境使用独立 profile seed
提供 A+B，不修改生产 migration。运维可以分别检查 Gateway 下游超时/契约错误和 problem-service 查询
耗时；管理端还能按 problem/version/testDataVersion 查询审计与部署状态。应用回退时保留兼容表和
不可变资产，不执行 Flyway clean 或删除已迁移数据；临时上传目录只由有界恢复任务处理。
