# IMPROVEMENT-001：重设计后台题目创建与编辑体验

## 当前问题

后台题目工作台虽然已经能够保存题面、上传测试数据、完成校准和发布，但它把这些能力按接口和数据字段
从上到下铺在一个长页面里。出题人员需要自己记住先后关系、判断按钮为什么不可用，并在滚动到页面底部
后才知道缺少哪些发布条件。题目列表与新建表单也挤在同一首屏，管理已有题目和创建新题互相干扰。

长内容目前主要使用普通文本域，样例甚至要求直接编辑 JSON；两处代码输入使用 Monaco。它们都能提交
数据，却没有形成一致、适合后台录入的编辑体验。页面还缺少持续可见的保存状态、离开保护、分步进度和
对底层单位的友好换算，因此一次填写时间越长，误操作和内容丢失的风险越高。

## 当前数据

2026-09-03 在已登录的本地真实页面完成只读走查，基线如下：

- 一个工作台同时承载题面、样例、起始代码、测试数据、部署校准、发布和版本危险操作，窄屏需要连续滚动
  多个视口才能走完；唯一保存按钮位于顶部，发布检查位于底部。
- 题面相关的五个长内容字段使用 Textarea；样例使用一个 JSON Textarea；起始代码和参考程序使用两个
  Monaco 实例。
- 创建动作固定使用 ACM/C++，但入口没有解释该默认值；失败文案也把不同原因统一归为“标识重复”。
- 发布检查已经提供 CONTENT、SAMPLES、LANGUAGE、TEST_DATA、DEPLOYMENT、CALIBRATION 六项稳定检查，
  但只有用户主动滚动到底部并运行后才可见。
- 当前没有产品埋点。本工作以真实浏览器任务完成情况、自动化行为断言、可访问性检查和管理端构建产物
  体积作为可复现基线，不虚构完成率或节省时长。

## 目标指标

- REQ-001：题目管理页以搜索、状态筛选和列表为主任务；“新建题目”改为独立按钮和短对话框，不再让
  创建表单长期占据列表首屏。
- REQ-002：创建对话框按“标题—标识—难度”组织，明确 ACM/C++ 初始配置；标识提供格式说明、示例和
  字段级错误，创建成功后进入新草稿工作台。
- REQ-003：工作台改为“基本信息、题面、样例、起始代码、测试与校准、检查与发布”六步流程；当前步骤
  进入 URL，刷新、前进后退和分享地址都能恢复。
- REQ-004：上下文栏持续显示题目、版本、生命周期和保存状态；保存操作在滚动中仍可到达，支持
  `Ctrl/Cmd+S`。首版使用明确保存而非静默自动保存，并在存在未保存内容时拦截站内离开和浏览器关闭。
- REQ-005：后台长篇 Markdown、长篇纯文本与代码输入统一使用项目封装的 CodeMirror 6 编辑器，不再用
  Textarea 或 Monaco。项目维护 React 适配、主题和扩展配置，不 fork 或复制上游编辑器内核。
- REQ-006：Markdown 编辑器支持“编辑、分屏预览、预览”模式；窄屏退化为编辑/预览切换。预览继续使用
  既有安全渲染链路，不执行原始 HTML。
- REQ-007：样例改为结构化卡片，支持新增、复制、删除和排序；序号由系统生成。标签改为可逐项添加和
  删除的输入，不再要求用户掌握 JSON、ordinal 或英文逗号协议。
- REQ-008：测试数据以“上传并绑定—部署—填写限制并校准”的依赖步骤呈现；界面使用秒和 MiB，提交时
  无损换算为现有 API 的 ns 和 bytes，不修改服务端单位与契约。
- REQ-009：发布检查在工作台导航和最终步骤中持续可见，六项检查能跳回对应步骤；发布、可见性、创建
  修订、归档和删除分组呈现，危险操作使用结构化确认对话框而不是浏览器原生确认。
- REQ-010：所有编辑器、步骤导航、对话框、错误和禁用原因在两个主题、键盘、320px、200% 缩放、
  中文输入法、forced-colors 和 reduced-motion 下可用；编辑器不得形成 Tab 键陷阱。
- REQ-011：本工作不改变 Problem、ProblemVersion、测试数据或发布 API，不修改后端服务、数据库、公开
  题库和用户端答题编辑器；若实现发现必须扩展接口，先更新本工作边界并重新提交意图审核。
- REQ-012：把本次反例和经过校正的编辑器选择原则写入 `docs/design-system.md`：长且结构化/语法敏感的
  内容使用设计系统编辑器，短多行纯文本仍可使用 Textarea；Monaco/CodeMirror 按任务复杂度选择，不能
  简化成“前台/后台”身份判断。

## 影响范围

影响 Web 管理端题目列表、题目版本工作台、路由搜索参数、表单状态、通用编辑器组件、依赖与对应测试，
以及 Web 工具链和长期设计系统说明。接口、数据库和后端服务保持不变；现有草稿数据可直接由新界面读取。

## 主要风险

风险集中在受控 React 表单与 CodeMirror 状态同步、rowVersion 保存冲突、步骤拆分后字段不应卸载丢失、
编辑器键盘/中文输入法行为、主题切换、管理端懒加载体积，以及把“减少复杂度”误做成隐藏必要状态。
必须保留服务器真实状态和失败恢复入口，不能用前端步骤完成度冒充发布就绪。

## 验证方式

- AC-001：题目列表首屏只出现创建入口、筛选和列表；创建对话框可通过指针和键盘完成、取消并恢复焦点，
  ACM/C++ 默认值和 slug 规则在提交前可见。
- AC-002：六个步骤均可通过步骤导航和 URL 直达，刷新与前进后退保持步骤；切换步骤不丢失尚未保存的
  表单内容。
- AC-003：编辑任一持久化字段后出现“有未保存内容”，保存中、已保存、保存失败和冲突状态均可复现；
  `Ctrl/Cmd+S` 可保存，站内/浏览器离开保护只在确有未保存内容时出现。
- AC-004：题面、输入、输出、数据范围、提示、样例长字段、起始代码和参考程序均由本地 CodeMirror
  封装承载；生产代码不再导入 Monaco，相关依赖和过期工具链说明被移除。
- AC-005：Markdown 的三种视图模式工作正常，预览继续净化不可信内容；空预览不占据无意义的大块空间，
  320px 下不强行分屏。
- AC-006：普通用户无需编写 JSON 即可新增、复制、重排和删除样例；保存请求生成连续 ordinal 和原有
  ProblemSample 结构，非法或空字段在对应卡片旁说明。
- AC-007：上传成功后自动绑定当前草稿；绑定失败时保留已上传的 READY 数据并提供重试。部署与校准按
  前置状态启用，每个禁用操作都有可读原因。
- AC-008：1 秒/256 MiB 等界面值提交为现有 ns/bytes 精确值，从服务端状态恢复时反向展示一致；无效、
  越界或非整数值在请求前被阻止。
- AC-009：进入最终步骤自动运行发布检查，未通过项可定位对应步骤；确认发布只在服务端返回 ready 后
  启用。危险操作与普通保存不在同一操作组，均使用项目 Dialog。
- AC-010：组件测试、Storybook、Playwright 和人工浏览器矩阵覆盖两个主题、键盘、中文输入、320px、
  200% 缩放、forced-colors、reduced-motion 与屏幕阅读器可访问名称；状态不只靠颜色表达。
- AC-011：OpenAPI、生成 API 类型、后端服务和数据库无改动，现有草稿/版本/测试数据可直接继续编辑；
  公开题库和认证回归通过。
- AC-012：`docs/design-system.md` 能明确解释何时使用 Input、Textarea、CodeMirror 与 Monaco，并记录
  长表单、原始 JSON、隐藏依赖、远距离保存按钮、无解释禁用和危险操作混放等禁止模式。

## 持续观察

合入后持续观察管理工作台懒加载 chunk、保存冲突/失败测试、上传后绑定失败恢复和编辑器异常日志。若新
编辑器让管理 chunk 明显大于移除 Monaco 前、中文输入或读屏行为退化、步骤恢复不可靠，视为改动失败并
回退编辑器或步骤壳层；不能以“视觉更整洁”为理由接受任务完成率下降。
