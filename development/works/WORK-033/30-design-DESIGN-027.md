# DESIGN-027：后台题目工作台 UI 设计

## 背景

依据 `IMPROVEMENT-001` 和 `EXPERIENCE-017`。现有页面沿用 Cherry OJ 的色彩、字体和基础组件，但把
七类任务垂直堆叠成一个长表单，并混用 Textarea、原始 JSON 和与主题割裂的 Monaco。此设计不更换视觉
语言，而是在既有 Focused Workspace 方向内重新建立信息层级、编辑器合同和任务状态。

## 目标与限制

- 用户在任意时刻只需理解当前一步，同时持续看见题目身份、保存状态、总体进度和发布阻塞。
- 普通分组优先使用间距和分隔线，不把六个步骤做成一屏 Card 仪表盘，也不增加宣传式 title/desc。
- 两个主题只消费语义 token；不新增 raw 色值、主题分支或页面私有间距。
- 桌面管理壳层仍只滚动中央 main；sticky 工作台栏必须位于该滚动容器内，不固定到浏览器 document。
- 不在 Figma 建立第二真源。本文是 UI 评审依据，真实组件状态仍以 Storybook 和浏览器验收为准。

## 整体方案

### 题目管理页

首行使用单一工具栏：左侧搜索与状态筛选，右侧主按钮“新建题目”。其下直接进入表格和分页。创建对话框
宽度以约 32rem 为上限，字段单列排列；标题获得初始焦点，slug 下方持续显示规则/示例，底部为“取消”
和“创建草稿”。ACM/C++ 以信息行展示，不画成不可操作的 Select。

### 工作台框架

工作台由三层组成：

1. **sticky 上下文栏**：返回入口；题目标题、slug/vN 和状态；保存状态；“保存草稿”和“检查发布”。
2. **步骤导航**：桌面左侧约 13rem 的 sticky 纵向导航；每项含序号、名称和文字状态。中窄屏改为顶部可
   横向滚动步骤条，320px 改为带当前状态的 Select/Popover，不重复渲染两套业务状态。
3. **步骤内容**：正文最大宽度约 64rem，以 field group、留白和分隔线组织。底部提供“上一步/下一步”，
   下一步不等于保存；有错误时先聚焦本步骤错误摘要。

上下文栏和步骤导航使用现有画布、panel、subtle、border、foreground、status 与 focus token。保存状态
以“有未保存内容/正在保存/已保存/保存失败”文字配图标表达，不新增颜色语义。

### 长内容编辑器

`TextEditor` 视觉结构为 label/required → 可选工具栏 → 编辑面 → description/error。编辑面使用设计系统
控件边界和 focus outline；正文等宽字体、行高和 selection 均消费 token。默认高度：题目正文约 24rem，
输入/输出/范围/提示约 12rem，代码约 22rem；均允许“展开编辑”，而不是随全文无限增高挤长页面。

`MarkdownEditor` 工具栏提供“编辑 / 分屏 / 预览”和“展开”。桌面分屏按 1:1；预览为空时只显示紧凑
占位，不保留与编辑器等高的大空白。小于桌面宽度不提供分屏，只保留编辑/预览切换。Markdown 工具栏
首版不提供会改变正文语义的 WYSIWYG 按钮。

代码编辑器沿用同一外壳，显示行号、括号匹配、搜索、撤销/重做与 C++ 高亮，不提供后台当前用不到的
智能补全、minimap 或 VS Code 级命令面板。每个实例的标签直接写出“C++ 起始代码”或“C++ 参考程序”。

### 基本信息与样例

基本信息使用单列/双列响应式 field group。标签输入以 chip 呈现：输入后按 Enter 或逗号添加，Backspace
可删除最后一项，重复项不添加并给出提示。

样例使用扁平的有边界分组而非嵌套 Card。标题行为“样例 1”和拖动/上移/下移、复制、删除；内容为输入、
输出、可选解释三个编辑器。编号只来自当前顺序。默认至少保留一个空样例；删除最后一个时回到空状态，
不会把内部数组或 ordinal 暴露给用户。

### 测试、校准与发布

测试链路使用垂直三步状态组件，每一步显示“未开始/进行中/可用/失败”、当前结果和唯一主动作；后一步
禁用时紧邻显示原因。测试数据列表默认展示创建时间、组数、总大小和是否用于当前版本；完整 hash 放在
可展开“技术详情”。限制输入显示 s/MiB，帮助文字可展示换算后的 ns/bytes，但不让底层单位成为主标签。

发布步骤顶部是六项检查列表。每项含状态、服务端文案和“去完善”链接；通过项可折叠。发布主按钮与检查
结果同组。可见性和创建修订放“版本操作”，归档与删除放独立危险区，并使用项目 Dialog 展示对象、影响
和不可逆边界。

## 模块与数据

- 通用 UI：CodeMirror 外壳、Markdown 编辑器、编辑器主题/扩展、标签输入和步骤导航。
- 题目业务组件：创建对话框、工作台框架、六个步骤、结构化样例、测试链路和发布检查映射。
- 现有 API 数据结构不变；UI 的秒/MiB、标签 chip 和样例卡片只在提交边界转换。
- 不新增 token。若实现发现现有 token 无法表达编辑器状态，必须按设计系统例外流程先补合同，不能在
  页面里写私有色值。

## 接口与状态

所有交互覆盖 default、hover、pressed、focus-visible、disabled、loading、error 和 success。禁用按钮
必须同时有文本原因；tooltip 不能成为唯一说明。步骤导航完成度来自表单和查询状态的纯派生，不单独持久化。

编辑器受控值更新不能重建实例或重置光标；主题变化只重配主题扩展。错误摘要在步骤内容顶部，字段错误
与编辑器通过 `aria-describedby` 关联。Dialog 打开后聚焦标题/首字段，关闭回到触发器。

## 安全与失败

Markdown 预览继续通过 `SafeMarkdown` 净化；编辑器不执行用户内容。参考程序不得进入 Query、URL、
localStorage/sessionStorage、日志或错误详情。危险操作 Dialog 不把确认等同于成功，结果不明时刷新资源
状态。保存冲突必须保留本地可选择/复制内容。

## 监控与部署

UI 无独立部署和埋点。验收记录管理路由 JS/CSS 产物体积、编辑器首次加载、保存/上传/绑定/部署/校准的
可观察状态；正式监控继续使用现有请求日志和 request ID。

## 迁移与兼容

现有草稿直接映射到结构化字段：samples 数组生成卡片，tags 数组生成 chip，ns/bytes 转为 s/MiB。
不改变保存 payload。旧书签没有 `step` 时进入“基本信息”；未知 step 回退该默认值。浏览器回退可以整体
恢复旧工作台，无数据迁移。

## 备选方案

- 顶部六个 Tab 且内容全卸载：窄屏更紧凑，但易丢字段状态和方向感；采用响应式步骤导航，表单状态常驻。
- Accordion 保留单页：仍需要在发布、保存和数据链路间长距离滚动，不能解决主问题。
- 每一步独立路由与独立保存：链接最清晰，但现有单一版本保存接口会造成跨步骤一致性和 rowVersion 复杂度；
  采用同一路由 `step` 搜索参数和统一保存。
- WYSIWYG Markdown：降低语法门槛但引入双向转换和内容漂移；首版保留源码编辑 + 安全预览。

## 风险与重审条件

额外 sticky 层可能压缩小屏可用高度；步骤过多也可能让简单题显得繁琐。验收必须用真实 320px、桌面和
长中文检查。未来支持 CORE、多语言或多人协作时，步骤与保存模型需重审；出现成熟协作/自动保存服务端
契约后再考虑自动保存，而不是只在前端增加定时请求。
