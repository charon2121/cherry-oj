# EXPERIENCE-017：后台题目创建与编辑 UX 流程

## 体验类型

以题目作者和题库运营人员为主的后台创作体验，同时覆盖编辑器组件的开发体验。目标不是让页面显得更短，
而是让使用者随时知道自己正在完成哪一步、内容是否安全保存、下一步是什么以及发布被什么条件阻塞。

## 入口与主流程

### 1. 管理与创建分离

题目管理页打开后直接显示工具栏、筛选和题目列表。工具栏右侧只有一个主要动作“新建题目”。点击后打开
短对话框，焦点进入标题；标题、题目标识和难度完成后提交。对话框明确说明首版按 ACM/C++ 创建，避免把
固定能力伪装成选择项。创建成功关闭对话框并进入草稿，失败停留原处并在字段或表单摘要中说明真实原因。

### 2. 工作台保持方向感

工作台顶部是位于主滚动容器内的 sticky 上下文栏：返回题目管理、题目名称、slug/vN、草稿/公开状态、
保存状态以及“保存草稿”“检查发布”。它不是宣传式页面标题，而是正在编辑的业务对象和全局操作。

其下是六步导航：

1. **基本信息**：标题、难度和标签，读取创建时的 slug 与 ACM/C++ 范围。
2. **题面**：题目正文、输入说明、输出说明、数据范围和提示。
3. **样例**：按卡片编辑输入、输出和解释，由系统维护顺序。
4. **起始代码**：为选手提供 C++ 初始模板，说明留空的效果。
5. **测试与校准**：上传并绑定测试数据、部署、填写友好单位的限制、运行参考程序。
6. **检查与发布**：自动读取六项服务端检查，逐项返回相应步骤，全部通过后确认发布。

步骤名、当前状态和可恢复 URL 同步。步骤状态只有“未开始、进行中、已完成、需处理”，均显示文字和图标，
不只使用颜色。前端完成度帮助导航，发布资格始终以服务端 publish-check 为准。

### 3. 保存模型

首版采用明确保存：任何持久化字段变化后显示“有未保存内容”；保存时显示“正在保存”，成功显示最近保存
时间，失败保留本地输入。保存按钮持续可见，并支持 `Ctrl/Cmd+S`。存在未保存内容时，切换工作台步骤不
拦截，离开题目工作台或关闭页面才确认。这样既避免长文丢失，也不让 rowVersion 接口在每次按键时产生
连续写入与冲突。

参考程序不属于草稿持久化字段，仍不写入缓存、URL 或存储。输入参考程序后离开工作台也要明确提示它会
丢失；校准提交成功后清空并告知用户。

### 4. 编辑长内容

Markdown 编辑器默认显示编辑视图，可切换分屏或安全预览。正文以适合连续写作的高度打开；输入/输出等
较短章节使用紧凑高度并允许展开。窄屏只在“编辑”和“预览”间切换，不把两列压窄。

样例不再暴露 JSON。每张样例卡直接包含输入、输出和可选解释；新增、复制、上移、下移与删除动作围绕
当前样例提供，删除已有内容需要确认。保存时由系统生成连续序号。

### 5. 数据与发布形成可见链路

测试与校准步骤把依赖表达为三个有序状态：“准备测试数据”“部署到当前环境”“运行参考程序校准”。上传
动作语义为“上传并用于此版本”，上传完成后自动尝试绑定；若绑定失败，已上传数据仍留在列表并提供
“重新绑定”，不要求用户重新上传。

资源限制用秒和 MiB 输入，旁边说明最终会换算为判题系统单位。每一步在不可操作时直接说明缺少的前置
条件，不让用户靠点击禁用按钮猜测。最终发布检查进入页面即运行，未通过项可跳回对应步骤。

## 异常状态

- 工作台加载失败：不挂载空表单，保留返回列表和重试；显示 request ID（若有）。
- 保存冲突：保持本地内容，提供“复制本地内容”和“加载服务端最新版本”，不自动覆盖或静默合并。
- 创建校验失败：slug 格式/重复归字段，服务不可用归表单摘要；不能一律提示重复。
- 编辑器加载失败：字段显示错误和重试，不自动降级成可能截断内容的短输入框。
- 上传失败：区分取消、格式错误、大小限制、网络/服务故障；结果不明时刷新数据列表。
- 自动绑定失败：展示 READY 上传结果和单独重试绑定，不重复上传。
- 部署/校准失败：保留已绑定数据、限制和参考程序（校准明确成功前），显示安全原因和重试。
- 发布检查失败：旧公开版本不受影响，页面保留各步骤内容并允许重新检查。
- 已发布/归档版本：编辑控件按服务端状态只读或禁用，并解释需要创建修订还是恢复题目。

## 交互与文案

主要动作使用“保存草稿”“上传并用于此版本”“部署测试数据”“运行参考程序校准”“发布此版本”等完整
动词。`READY`、hash、ordinal、ns、bytes 只在高级详情中作为诊断信息出现，默认界面使用“可用”、
“共 N 组”、秒和 MiB。

“公开/私有”描述题目是否允许公开访问，“发布”描述哪个不可变版本成为当前版本；两者不得使用同一个
按钮或相邻主动作造成等价暗示。创建修订归版本菜单，归档题目和删除草稿归危险操作区。

Textarea 仍可用于短备注、拒绝原因等简单多行纯文本。是否使用编辑器取决于内容长度、结构、搜索/撤销
需求和语法提示，不取决于页面属于前台还是后台。

## 可访问性

六步导航使用可识别的导航/列表语义，当前步骤有 `aria-current`；窄屏选择器保留同一名称和状态。每个
CodeMirror 实例拥有唯一、业务化的可访问名称、描述和错误关联，不出现多个同名“Editor content”。

编辑器默认不接管 Tab 导航；若提供缩进快捷键，必须同时提供可发现的退出方式和帮助说明。工具栏、样例
排序、对话框、上传和发布全程可用键盘操作并保持焦点恢复。中文输入法组合期间不得触发保存、校验或值
回写打断输入。状态更新通过克制的 live region 宣告，不在每个按键时播报。

320px 下步骤导航、保存按钮和样例动作不被裁切；Markdown 分屏关闭，长代码使用编辑器内部滚动。200%
缩放、forced-colors、reduced-motion 和两个主题下保持可见焦点、边界和错误语义。

## 调试与恢复

URL 的 `step` 是唯一可恢复导航状态；表单值归 TanStack Form，服务端状态归 Query，编辑器只做受控输入
适配，不建立第二份业务真源。调试时可分别观察保存、上传、绑定、部署、校准和发布检查请求及 request ID。

若步骤壳层或 CodeMirror 在关键浏览器上失败，可独立回退到原工作台组件；API 和数据没有迁移。回退不
恢复 JSON 作为长期方案，后续修复仍应保持结构化样例合同。
