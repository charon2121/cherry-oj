# EXPERIENCE-001：正式提交与结果恢复

## 体验类型

面向答题用户。复用 WORK-041 的 WorkbenchPageTemplate coding 模板、Monaco 与触屏编辑器，
不重新设计题目页。实施前读取 Web 设计系统入口并完成自检七问。

## 入口与主流程

1. 登录后打开已发布 C++ ACM 题目，编辑完整程序。提交按钮启用，运行仍显示暂未开放。
2. 点击提交时捕获当前源码与题面版本；按钮显示“正在提交”，避免连续点击。
3. 创建成功后显示编号、时间、题目版本、语言和结果区域；地址记录提交编号，提供复制结果链接。
4. 结果区从“排队中”到“判题中”，最终显示文字 verdict 和允许公开的资源信息。轮询可能跳过很短的中间状态。
5. 用户可以继续改代码；结果标明属于之前提交，新源码仅在下次明确提交时送出。

## 异常状态

| 状态 | 用户看到什么 | 恢复方式 |
|---|---|---|
| 未登录或必须改密 | 登录/改密提示，源码仍在既有草稿中 | 完成后重新确认提交 |
| 创建响应未知 | “暂时无法确认是否已提交” | 只提供确认原请求；不自动创建新请求 |
| 题面已更新 | “题目已更新，请刷新题面后重新确认” | 保留旧草稿恢复副本，按 WORK-041 版本隔离规则恢复 |
| 无可用节点、无 VALID 校准 | “当前题目暂时无法判题”与请求编号 | 稍后重试；不展示后台地址或自动修改校准 |
| 已创建但查询失败 | 保留编号与上次结果，显示“结果暂时无法获取” | 重试 GET 原记录 |
| 排队较久 | 显示仍在等待，不假造 WA/SE | 后端有界恢复；终态以服务器事实为准 |
| CE / WA / SE | 区分代码错误、答案错误、平台故障 | CE 展示安全诊断；SE 提示稍后明确重新提交 |
| 不存在或他人记录 | 统一“记录不存在或无权查看” | 返回题目，不泄漏归属 |

## 交互与文案

在题目页查询参数记录 submissionId（实际参数名由契约任务冻结）；查询该 ID 的归属与题目必须由服务端检查。
退出登录/切换账号立即停止轮询并清除内存中的结果；登录后只可恢复当前账号自己的记录。
待确认的创建请求按账号隔离，保存幂等键、请求摘要与必要原请求信息，不复用正在变化的编辑器内容。
刷新只读取原请求/原提交的状态；若需要重送 POST，用户明确点击恢复且保持原键和原请求正文。
恢复信息不可用或存储受限时说明无法自动恢复，可凭已知编号查结果，不能声称已确保恢复成功。

## 可访问性

提交按钮键盘可达、处理中状态可感知。状态区采用适度的 live 提示，只在状态改变时播报，
不在每次轮询抢焦点。错误与 verdict 不只靠颜色。窄屏在现有题面/代码切换结构中能访问结果。

## 调试与恢复

面向用户展示请求编号和提交编号，便于管理员查找；不展示 token、节点地址、数据库错误或原始事件。
手工验收脚本见 VERIFY；完成本轮不要求用户阅读实现代码。
