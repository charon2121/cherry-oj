# PLAN-002：六个任务完成正式提交闭环

## 目标

交付 FEATURE-001 本轮十项验收，不实现后续自定义运行与完整历史。当前回合仅整理文档，
WORK/TASK 保持 todo；负责人审核文档、签署意图闸并允许执行后才进入实施。

## 改动区域

契约和内部鉴权基础、problem/judging 的内部快照、submission 持久化、judging 异步编排、
Gateway 与现有题目页，以及专用隔离验收脚本。详细允许路径在每个 TASK 的元数据中。
新增任务的目录授权只服务于其任务目标，不意味着允许重构整个模块。

## 阶段与顺序

| 顺序 | TASK | 可检查的产出 | 前置 |
|---|---|---|---|
| 1 | TASK-002 | 公开/内部 API 与安全事件契约、服务身份基础和契约负向测试 | 上游确认、意图闸、执行授权 |
| 2 | TASK-076 | 指定当前题目与执行配置的受保护快照；无就绪条件明确拒绝 | TASK-002 |

采用这个顺序便于逐步解释与验收；前几任务的测试替身只验证模块边界，不能当作真实整链路完成。
各阶段结束给出“现在能做什么、还不能做什么”的简短说明和实际测试结果。

## 并行与依赖

默认串行，不自动启用子智能体。若后来明确授权并行，可以在契约稳定后处理无重叠文件的工作；
共享契约由 TASK-002 单独负责，snapshot 与 Worker 修改 judging-service 时不得同时覆盖同一文件。
独立复核是本工作必做检查，TASK-080 前取得独立审查人的结果，或在获得授权后使用只读子智能体。

## 迁移与交付

先在隔离数据库应用增量迁移与凭据配置，准备独立 Kafka topic/consumer group 和测试节点、数据、VALID 校准，
再接通服务与 Web。隔离脚本使用独立 Compose project、端口和数据目录，不使用现有运行环境的数据库或卷。
既有 compose.yaml 仅含引擎，不把它误认为完整测试栈；TASK-080 新建专用测试 Compose，不改原运行配置。

TASK-002 先冻结契约、字段上限、错误码、幂等摘要、服务身份配置、执行预算所需元信息和安全事件结果。
若后续发现契约缺口，退回 TASK-002 更新依据和兼容验证，不能在模块任务中擅改 contracts。
Java 数据迁移沿用 Flyway/MySQL；只能新增 migration。依赖只加到需要的 pom，不创建通用消息框架。

负责人已确认隔离栈完整验收，现有环境另行确认部署后人工冒烟；本轮不直接部署现有环境。交付材料列出迁移顺序、配置名称（不包含密钥）、
节点/数据/校准就绪条件、启动命令与恢复步骤。正式环境部署需要负责人在看过具体部署材料后另外授权。

## 风险

任务必须同时防止重复受理、消息重投、租约迟到、身份混用和隐藏结果泄漏。完整异步链不能仅凭模拟测试声明可用。
节点注册和校准属于依赖回归；缺 VALID 不能让本工作自动补默认校准。服务身份与事件 schema 收窄是重点独立复核项。

## 验证

TASK-002：契约正反例、用户凭证/错误调用链/旧凭据撤销后的拒绝。
TASK-076：发布状态、旧版本前置条件、无 VALID、节点 session 过期、错误数据摘要。
TASK-077：真实 MySQL 并发同键、事务回滚、响应丢失恢复、越权查询、Outbox/Inbox 故障。
TASK-078：真实 Kafka、重复/乱序、重启/租约恢复、指纹不符、AC/WA/CE/TLE/SE与敏感字段投影。
TASK-079：既有 Web 检查、结果轮询与账号切换、草稿回归、键盘/窄屏/读屏状态。
TASK-080：真实 Linux 引擎与 Java 全链路，按 VERIFY 十项 AC 留下可复现证据及独立复核。

## 回退

1. 先关闭 Gateway/前端新的提交入口，保留已有结果查询，阻止新受理。
2. 停止受理后让在途任务完成；无法完成的任务按原规则恢复/收敛，保留提交与消息定位证据。
3. 停 Worker/发布器前确认 Outbox 和租约状态；恢复时从持久状态续跑，不能清 topic、删 Inbox 或批量改 verdict。
4. 回退应用时保留新表和数据，不执行破坏性 down migration；旧版本无法继续读写新增事实时先保留对应服务版本。
5. 隔离测试只删除脚本自己创建的资源；现有环境不清库、不删卷、不替换测试数据或既有校准。

演练入口禁用、在途任务恢复、原题目/编辑器仍可使用，并记录命令和结果；只写回退步骤不算验证通过。
