# EXPERIENCE-021：重构回归的开发体验

## 体验类型

开发与验收体验，无新增产品页面。

## 入口与主流程

开发者查看提交或 PR 的 CI，先读汇总，再展开基础、Linux 隔离、原生部署和真实业务报告。每项标明场景 ID、执行状态、源码 SHA、环境及证据位置；红色条目直接指向失败阶段和重现命令。手动触发仍验证所选 ref 的精确 SHA。

## 异常状态

能力缺失显示环境失败；断言失败显示测试失败；报告缺失、取消和清理未确认单独列出。前置失败导致未执行的用例不能被算作通过。工具链下载失败与代码失败分别说明，但整个必需验证仍不通过。

## 交互与文案

统一使用 PASS、FAIL、ENVIRONMENT_ERROR、CANCELLED、NOT_RUN；允许说明性 SKIP，但必需清单中出现 SKIP 即不通过。无需把完整原始日志读完才能知道哪些场景没运行。

## 可访问性

使用 GitHub 现有检查界面与可下载文本/JSON，不新增交互组件；结果同时带文字，不能只靠颜色区分。

## 调试与恢复

报告给出仓库内相同 suite 入口。重跑生成独立 run ID 和新资源，不覆盖上次失败证据。停止只作用本次登记的资源；禁止为了排错连接当前用户服务。独立复核和人工验收仍按工作流程执行。
