# EXPERIENCE-005：建立用户身份与访问控制服务

## 体验类型

同时覆盖用户体验、管理员体验、开发接入体验和密钥/管理员初始化的运维体验。安全状态必须清楚，但
公开文案不能为了“说清楚”而泄露某个用户名是否存在、是否停用或是否被临时锁定。

## 入口与主流程

浏览器启动先读取 CSRF 与当前 Session：未登录时停留在原目标页并显示登录入口；登录成功后更换 Session
ID，回到用户原本想访问的页面。首次登录若使用临时密码，只允许进入改密流程；改密成功撤销全部登录，
用户使用新密码重新登录。主动退出仅结束当前浏览器。

管理员从用户管理入口查看稳定分页列表，创建普通用户并得到只展示一次的临时密码交付提醒；可以停用、
恢复或重置密码。危险操作明确展示目标用户名并二次确认，提交中禁用重复操作，成功后刷新当前事实。

## 异常状态

- Session 检查中：显示稳定骨架，不短暂闪出受保护内容或错误跳转。
- 未登录：引导登录并保留安全的站内 return path；拒绝外部 URL 和协议相对跳转。
- 凭据错误：统一显示“用户名或密码错误，或账号暂不可用”，不区分具体原因。
- 限速：显示稍后重试并尊重 `Retry-After`，不自动高频重放密码。
- 401：只有明确过期/撤销才清理本地 Session 状态；下游 503 保留页面与重试入口。
- 403：显示“当前账号无权限”，不伪装 404，也不循环跳转登录页。
- 必须改密：除退出和改密外的受保护导航都回到改密页。
- 管理列表：分别处理 loading、empty、error、unauthorized 和 success；失败不丢失已显示的数据。

## 交互与文案

输入框带可见 label、密码显示切换和大小写状态提示；提交按钮使用“登录”“修改密码”等具体动词。
错误摘要不回显密码或把用户名拼进服务端 detail。用户停用、重置与角色操作的确认文案必须说明“将结束
该用户全部登录”；临时密码只展示一次，页面离开后不能再次查询原文。

## 可访问性

表单可完全键盘操作，焦点在失败后移动到错误摘要并与对应字段关联；密码显隐按钮有可读名称，状态不只
靠颜色。登录与改密在窄屏可用，Session 检查和提交状态通过合适的 live region 宣告，但不重复播报。

## 调试与恢复

开发者从验证后的 principal 读取 userId/role，不直接解析不可信 header，也不接触密码。测试提供固定时钟、
临时密钥、假 Redis 与 Testcontainers MySQL，避免依赖共享开发账号。

运维初始化命令从终端标准输入读取密码，若已有 ADMIN 默认拒绝执行并留下审计；不把密码写入 shell
history、环境变量或 migration。轮换文档明确当前/上一把 `kid`、缓存等待期和回退步骤。值班排障使用
requestId、内部 trace 与安全审计动作，不查询或打印凭据正文。
