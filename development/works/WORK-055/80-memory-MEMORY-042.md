# MEMORY-042：避免让每个回归任务重复冷下载

## 背景

WORK-054两轮6VM中两次GCC正文未在600秒完成；无证据证明继续增加等待可稳定解决。详见VERIFY-055，不能归咎单一IP或把受限进度当最终字节。

## 决定与原因

当前待审核方案将日常包复用与独立冷下载分开。只缓存锁定包，不复用环境身份、标定或测试结果。此处记录提议，未宣称用户已签署或实现已通过。

## 尝试与教训

扩大等待没有产生240至600秒间完成的样本。统一准备减少重复公网请求，但必须保留无缓存部署验证。缓存与artifact需要独立内容校验，不能作为信任来源。

## 已知问题

TASK-112业务io与内核采样错误待WORK-050调查，WORK-049尚不能以本提案作为重构全绿基线。

## 重新考虑条件

冷获取仍失败、工具兼容需要膨胀、缓存无法安全交付或来源包消失时重审；不能静默换源或忽略冷检查。
