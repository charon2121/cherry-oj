# ISSUE-006：修复后台用户列表偶发误跳登录页

## 为什么做

管理员已经登录并能看到“管理中心”，但进入“账号管理 → 用户账号”时，偶尔会被带回登录页。此时
刷新页面又能识别出原来的登录状态，说明系统把一次后台请求失败误当成了整段登录失效。这个行为会
中断管理操作，也会让使用者误以为账号或密码出了问题。

## 问题现象

管理员登录后，从站点账号菜单进入管理中心，再打开“账号管理 → 用户账号”，页面偶发跳转到
`/login?returnTo=%2Fadmin%2Fusers%3Fpage%3D1`。在该登录页刷新后，已有登录状态仍可被识别，不需要
重新输入用户名和密码。

## 复现方式

已观察到的用户路径：

1. 使用 ADMIN 登录 Web，确认账号菜单显示“管理中心”。
2. 进入管理中心，点击“账号管理 → 用户账号”。
3. 多次重复进入该页面，或在本地 user-service 重启后、当前 120 秒内部令牌尚未进入刷新窗口时进入。
4. 观察是否跳到带 `/admin/users?page=1` returnTo 的登录页；在登录页刷新。

第 3 步的“服务重启”是从代码与本地默认配置得到的稳定触发条件，尚未对用户原始那一次失败抓取
`requestId`。本地默认签名密钥在 user-service 每次启动时重建，旧 Gateway Session 中尚未到期的内部
令牌会被新进程拒绝；这能产生与用户现象相同的“资源请求 401、Session 查询仍为已登录”。

## 实际结果

`GET /api/admin/users?page=1&size=20` 的单次 401 被 Web 直接写入共享 Session 缓存为“未登录”，随后
跳转登录页。该 401 也可能来自 user-service 对 Gateway 内部短令牌的拒绝；当前 Gateway 原样映射为
浏览器 401，却没有先用仍有效的登录授权换取新令牌，也没有删除 Redis Session。完整刷新清空前端
内存缓存后，`GET /api/auth/session` 因 Redis Session 仍在而再次返回已登录。

## 预期结果

只有浏览器 Session 或其背后的登录授权明确过期、撤销时，管理员才进入登录页。内部短令牌过期、
签名密钥切换或一次下游验签失败时，Gateway 应先在服务端恢复并重试；临时故障应保留 Session 并显示
可重试错误，不能伪装成退出。该语义沿用 CAPABILITY-004 REQ-009～REQ-011、EXPERIENCE-005 的“明确
过期/撤销才清理本地 Session”和 DESIGN-010 的下游错误映射边界。

## 影响与条件

直接影响 `/admin/users` 的首次列表加载及该页面后续管理操作。结构上涉及 Web Session 缓存、Gateway
保存的内部短令牌和 user-service 资源验签三层，但不改变账号、角色、密码、Redis/MySQL 表结构、公开
OpenAPI 或 Cookie 格式。默认本地临时签名密钥重建、令牌临近时间边界、并发刷新或未来密钥轮换都属于
必须覆盖的触发条件。

## 原因

已确认直接原因是错误语义越层：Admin 用户 BFF 将下游资源接口的 401 直接暴露成浏览器未认证，Web
据此把共享 Session 缓存改成匿名。它没有利用 Gateway 仍持有的登录授权确认“浏览器登录真的失效”。

用户原始那一次下游 401 的具体触发源尚无 `requestId` 证据；本地默认临时 RSA 密钥在 user-service
重启后变化，是代码可证明且与现象一致的一类触发源。修复不能只特判重启，而要覆盖“当前内部令牌被
资源接口拒绝、登录授权仍有效”的通用状态。

## 修复方向

在 Gateway 的 Admin 用户调用边界增加一次受控恢复：资源接口首次拒绝当前内部令牌时，使用服务器端
登录授权强制交换新令牌并只重试原请求一次。授权已撤销/过期才清理 Session 并返回 401；交换临时失败
或新令牌仍被拒绝时保留 Session，返回 5xx 可重试错误。并发恢复必须单飞，且每个并发 WebSession
实例都保存同一刷新结果，不能由旧状态回写覆盖。

Web 继续把经过上述确认后的公开 401 视为真正未登录，不让浏览器接触登录授权或内部令牌。

## 回归检查

- AC-001：ADMIN 在内部短令牌仍有效且下游正常时打开 `/admin/users?page=1`，列表只请求一次并正常显示，
  既有 401/403 行为不被放宽。
- AC-002：下游首次以 401 拒绝当前内部令牌、登录授权仍有效时，Gateway 强制交换一次、使用新令牌只
  重试一次并返回列表；浏览器不跳登录页，Session 仍为已登录。
- AC-003：强制交换确认登录授权已过期或撤销时，Gateway 清理浏览器 Session 并返回公开 401；Web 跳到
  带安全 returnTo 的登录页，刷新后也不能恢复旧登录态。
- AC-004：强制交换超时/5xx，或刚签发的新令牌仍被资源接口拒绝时，公开响应为 5xx 且保留 Session；
  页面显示可重试错误，不跳登录页，单个业务请求最多重试一次。
- AC-005：同一 Session 并发遇到令牌拒绝时只发生一次上游交换，所有参与请求保存同一新状态；旧的
  touch/令牌状态不能覆盖刷新结果，也不能泄露 Cookie、登录授权或 JWT。
- AC-006：用本地临时签名密钥切换（或等价受控假钥）稳定复现“旧短令牌被拒绝”，证明修复前的状态
  组合会误报 401，修复后无需重新输入密码即可恢复用户列表；正常登录、退出、改密、停用、角色不足
  与 CSRF 回归保持通过。
