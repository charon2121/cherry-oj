# DECISION-020：确定前景色四档合同、Tailwind alias 词汇表与样板页范围

## 要决定什么

三件会长期约束后续所有 Web 工作的事：

1. 前景色层级要恢复成几档、`fg-disabled` 是否继续受 4.5:1 约束；
2. Tailwind adapter 暴露多大的 alias 词汇表，业务代码被允许写什么；
3. 本次工作迁移几个页面。

## 背景

来源定义四档文字：`#f7f8f8` → `#d0d6e0` → `#8a8f98` → `#62666d`。实测在 `cherry-black` 画布上的
对比度分别是 18.73 / 13.64 / 6.13 / **3.45**。最弱一档达不到正文 4.5:1。

`theme-contract.json` 把 `--ds-fg-disabled` 的 `contrastClass` 定为 `text`（阈值 4.5:1）。这一条
决定了后果：为了过检，`cherry-black` 的 `fg-muted`、`fg-meta`、`fg-disabled` 被迫全取 `#8a8f98`，
`pure-white` 取 `#62666d` / `#676b73` / `#676b73`。四档塌成两档半，而且**禁用文字和普通元数据
变成同一个灰**——用户看到灰字分不清"这是补充信息"还是"这个功能不能用"。

这不是执行疏忽，是合同把一个 WCAG 明确豁免的对象当成了正文。WCAG 2.2 的 1.4.3 对
"inactive user interface component" 的文字不作对比度要求。把 disabled 按正文要求，等于强迫它
和可用文字一样醒目，反而消除了"不可用"这个信息本身。

第二件事：`apps/web/src` 有 807 处 `var(--ds-*)`，其中 244 处是间距。原因是 adapter 只 alias 了
颜色与 radius。这既让业务代码写 token 管道，也让 shadcn 官方组件难以接入——官方带的
`bg-muted p-4` 每次都要手改。

第三件事：构图层建好之后，是一次迁完所有页面，还是先做一个样板。用户在此之前已经经历过四轮
设计系统返工，核心症结始终是"做完才发现不像"。

## 候选方案

### A. 前景色层级

1. **维持现状（三档合一）。** 零改动、全部过检，但保留可用性缺陷，且来源的安静层级无法恢复。
2. **恢复来源四档原值。** 视觉最忠实，但最弱一档 3.45:1，正文可读性不达标，且 `pure-white`
   在来源中没有对应物，只能猜。
3. **四档压缩进达标区间，disabled 单独豁免。** 四档全部 ≥4.5:1 且彼此可分，把来源最弱那一档的
   位置让给 disabled（WCAG 豁免）。
4. **四档达标，disabled 继续按正文要求，靠字号或图标区分。** 不改合同，但 disabled 仍与 metadata
   同色，只能靠别的信号区分，问题没解决只是转移。

### B. Alias 词汇表

1. **只补颜色相关 alias。** 改动小，但 244 处间距用法无处可去，主要问题未解决。
2. **按业务代码实际用量补全类别**（间距、字号、字重、tracking、leading、motion、ease、
   三档透明 surface、四档前景、line、elevation、布局尺寸），并加 lint 禁止业务层写 `var(--ds-`。
3. **全量映射每一个 token。** 覆盖最全，但会产出大量无人使用的 alias，且鼓励绕过组件直接拼样式。

### C. 迁移范围

1. **一次迁完所有页面。** 一致性最快达成，但如果构图合同抓错特征，返工面是整个 Web——
   这正是前四轮反复发生的事。
2. **只迁题库列表作为样板，其余等用户确认后再迁。** 反馈最早，返工面最小；代价是仓库短暂并存
   两种列表写法。
3. **不迁页面，只交付组件与模板。** 无法验证构图合同是否真的能产出"像"的页面，等于把判断继续推迟。

## 决定

用户在 2026-09-03 明确把这三项判断委托给智能体（"3 个选择你帮我做决定吧，我不是专业的设计师"）。
以下为据此作出的决定；文档状态仍为 `review`，由用户在意图闸统一签署。

三项中只有 A 涉及视觉取舍，B 与 C 是工程判断：B 关于代码该怎么写，C 关于什么时候让人来看。

- **A-3**：四档压缩进达标区间，`fg-disabled` 改为 WCAG 豁免类别。
  实测建议值（两个主题全部允许 surface 均 ≥4.5:1）：

  | token | cherry-black | 最低对比度 | pure-white | 最低对比度 |
  |---|---|---|---|---|
  | `--ds-fg` | `#f7f8f8`（不变）| 13.80 | `#191a1b`（不变）| 15.83 |
  | `--ds-fg-2` | `#d0d6e0`（不变）| 10.05 | `#34343a`（不变）| 11.23 |
  | `--ds-fg-muted` | `#a8adb6`（新）| 6.52 | `#55595f`（新）| 6.40 |
  | `--ds-fg-meta` | `#8a8f98`（不变）| 4.52 | `#6b7079`（新）| 4.52 |
  | `--ds-fg-disabled` | `#62666d`（来源值，豁免）| 2.55 | `#9aa0a8`（豁免）| 2.39 |

  最低对比度取该 token 在 `--ds-surface-hover` 上的实测值，即全部允许 surface 中最严的一个。

- **B-2**：按实际用量补全 alias 类别，并同时加 lint。两者必须同批交付——只补 alias 不加 lint，
  两套写法会长期并存。

- **C-2**：只迁题库列表作为样板。

### A 的可感知代价（唯一需要你留意的一条）

`fg-muted` 从 `#8a8f98` 提到 `#a8adb6`，暗色界面里的次要文字会比冻结来源**略亮一点**。
这是拿视觉忠实换可读性：来源那一档在正文场景下只有 3.45–6.13:1，压到达标区间就必然要提亮。

样板页交付时这一点会直接看得到。如果你看完觉得整体偏亮，正确的调整方向是**减少次要文字的
使用量和分布**，而不是把对比度调回去——后者会让四档重新塌陷，等于绕回原点。

## 理由

**A-3 而不是 A-1/A-2/A-4。** A-1 保留缺陷；A-2 的最弱档 3.45:1 会让时间戳这类真实信息不可靠读取，
而时间戳不是装饰；A-4 把问题从"看不出禁用"转移成"必须再加一个信号才能看出禁用"，合同层面
仍然错误。A-3 承认一件事：**disabled 不是一档更浅的正文，它是另一类对象。** 把它移出正文约束后，
来源最弱那一档终于有了正确的归宿，四档也随之各就各位。

代价是 `fg-muted` 相对来源变亮（`#8a8f98` → `#a8adb6`），暗色界面会比来源略"响"一点。这是
可访问性与视觉忠实之间的取舍，选择了前者——把不可读的正文做忠实没有意义。这条取舍必须写进
`design-system.md`，否则下次对照来源截图时会被当成实现错误。

**B-2 而不是 B-3。** 全量映射会产出大量无人使用的 alias，并鼓励绕过组件直接拼样式；而本次工作的
目的恰恰是让页面**少**直接拼样式。alias 的判断标准是"业务代码真的需要它来表达任务"，
不是"token 存在所以要有 alias"。

**C-2 而不是 C-1。** 用户已经历四轮"做完才发现不像"。样板页的价值不在省工，在于把"像不像"
这个只能由人判断的问题提前到构图合同刚成型时问，而不是全站迁完后问。若样板被否，返工面是
一个页面加一份合同，而不是整个 Web。

## 影响与风险

- 四档调整影响每一个页面的次要文字外观，即使本次只迁一个页面。未迁页面必须做外观复查（AC-010）。
- `fg-disabled` 放宽对比度是有意降低可读性，与常规直觉相反。前提是 `design-system.md` §7.1 已经
  要求"禁用控件旁必须有持久、可读的原因"；若该规则未被遵守，放宽会让"为什么不能用"彻底无从得知。
  因此本决定与那条规则绑定，不能单独生效。
- lint 会拦住新代码里的 `var(--ds-`。若 alias 覆盖不全，开发会被卡住。缓解方式是把补 alias 与
  加 lint 放在同一批交付，并要求违例时补 alias 或补组件，而不是加例外。
- 样板期内仓库并存两种列表写法。必须在 `design-system.md` 明确这是过渡状态并指明承接工作。

## 重新考虑条件

- 用户看过样板页仍认为"不像"：说明构图合同识别错了特征，回到 DESIGN 重新识别，
  不要继续迁移其余页面。
- 四档调整后，暗色界面被判断为整体偏亮：重新评估 `fg-muted`，但不得以牺牲 4.5:1 为代价，
  正确方向是调整使用频率与分布而非降低对比度。
- 出现第三个正式主题：四档取值必须在新主题中重新标定，本决定的具体数值不跨主题复用，
  只有"四档达标 + disabled 豁免"这个结构是跨主题的。
- WCAG 后续版本对失效控件提出对比度要求：`fg-disabled` 的豁免前提消失，需要重新决定。
