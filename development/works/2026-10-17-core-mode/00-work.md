# C++ CORE 模式

类型：新增 · 创建：2026-10-17 · 状态：设计已定稿（2026-10-17），尚未授权实施

## 为什么做

CORE 是完整 MVP 的第二个切片（[`docs/product.md`](../../../docs/product.md) §3.2、§3.4 第 1、4 条）。现在只有 ACM 能走通：
数据库和契约预留了 CORE（`problem_language.judge_template`、`ProblemJudgeSnapshot.judgeTemplate`），但五个服务和前端
在每个入口都把 CORE 拦掉了。不做完它，就只能声明"ACM 切片完成"，不能声明完整 MVP。

## 打算怎么解决

用户只写核心代码，不用写任何 include/import，报错行号与编辑器一致。做法与 LintCode 实测的一致（[design.md](./design.md) §1）：

- 三段文本：**驱动代码**（题目 × 语言，不下发给用户）、**前缀代码**（每门语言一份，所有题目复用）、**模板代码**（给用户的起始代码）；
- **用户文件**（C++ 为 `solution.cpp`）= 前缀代码 + 用户代码，由 Java 服务合并；**驱动文件**（C++ 为 `Main.cpp`）= 驱动代码；
- judge 按契约里的固定文件名一起编译运行；judging-service 改写展示给用户的报错：用户文件行号减去前缀行数，路径只留文件名。驱动代码出现在报错里照常显示，不做遮掩；标准输出不改。

方案依据是 [multi-file-languages.md](./multi-file-languages.md)：13 门语言的写法（逐一实测）、LeetCode 与 LintCode 的实测、
统一改写原型在 13 门语言上的实测。全部决定见 design.md §9。

## 范围和代价

- **推翻已确认内容：** 决定 #4（唯一占位符替换）与 MVP 基线第 4 条（judge 只接收普通完整源码），以及 architecture.md、
  data-model.md 中的对应描述；实施前先改全局文档（design.md §3）。
- **会改的：** 契约（judge 请求与文件名、JudgeInput、自测、判题快照、管理端接口，新增标定契约）；judge（可选的用户文件）；
  problem-service（语言表与前缀、CORE 题目、标定合并）、judging-service（报错改写）、submission-service（合并与冻结）、gateway；
  管理端题目创建、驱动代码编辑与标定；用户端做题页放开 CORE；benchmark 加一道 CORE 题；e2e 补 CORE 场景。
- **不改的：** 执行层与 C 执行器、rootfs、测试数据协议、Kafka 事件、judging-service 的数据库。
- **用户可见变化：** 题库里出现可答的"核心代码"题；不写 `#include` 也能用标准库；报错行号与编辑器一致；签名写错时报错指向
  `Main.cpp`。
- **管理员可见变化：** 创建题目时选代码模式，之后不可修改；CORE 题多一个"驱动代码"编辑框；修改驱动代码或前缀后，标定不会自动失效，
  页面会提示"建议重新标定"。
- **先不做（控制前期复杂度，以后再考虑，见 design.md §8）：** 改动后标定自动失效、前缀的管理界面、报错里遮蔽驱动代码、通用函数签名与驱动代码生成、C++ 以外的语言、诊断映射到编辑器标记、驱动代码版本历史、"我的提交"页。
- **数据库：** 开发阶段直接改写 problem-service 的 V1（新增语言表、驱动代码修改时间），重建开发库。

## 怎样算完成

- 管理员能创建、编辑、标定并公开一道 C++ CORE A+B。
- 普通用户在该题上不写任何 `#include`，完成编辑、样例运行、自测、正式提交、结果和历史回看；AC、WA、CE、RE 都能得到；
  用户代码的编译错误与运行错误显示 `solution.cpp:<编辑器行号>`；函数签名写错时报错指向 `Main.cpp`。
- 任何接口都不把驱动代码下发给普通用户（e2e 中断言浏览器响应里没有驱动代码全文）。
- 修改驱动代码或前缀后，管理端出现"建议重新标定"的提示。
- judging-service 的改写单元测试覆盖 13 门语言的真实输出样例，以及驱动文件、前缀行、截断三类样例；benchmark 的 CORE 题在真实节点上通过。
- 隔离栈 e2e 在原有 ACM 场景之外跑通 CORE 场景并留下证据，再更新 `docs/status.md`。
