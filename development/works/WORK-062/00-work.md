# WORK-062：将开发文档流程改为明确调用的仓库 skill

类型：维护 · 历史工作

## 为什么做

文档流程默认强制启动，长文和状态管理挤占开发及审核时间。

## 打算怎么解决

将流程改成明确调用的仓库 skill，保留五类任务，并迁移旧工作入口。

## 范围和代价

普通开发不创建工作文档；保留工程规范、原始历史和真实证据。用户明确豁免本次旧 WORK 流程。

## 怎样算完成

明确调用才启动；每项工作有短说明；旧资料可查；不再强制签闸或创建编号任务。

## 结果与验证

仓库专用 `$dev-work` 已就位，配置禁止自动调用；五类任务的流程与材料有明确规则。全局入口、产品与编码文档、hooks 和 CI 已同步，旧状态管理命令移除，新工作默认只有一份短说明。

62 个入口已迁移，61 份原主文档与 Git 原版本逐字一致，574 份历史原件摘要一致，旧系统快照可解包。8 项记录工具测试、4 项链接校验器测试、637 份文档的链接检查和模拟提交 hook 通过；skill YAML 与显式调用策略通过现有 YAML 解析器校验。用户已要求本地提交，使用体验仍需后续实际任务反馈。

早先按旧流程准备的方案已归档；本次以用户后续豁免和迁移要求为准。
