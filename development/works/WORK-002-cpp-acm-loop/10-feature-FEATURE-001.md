# FEATURE-001：交付 C++ ACM 答题闭环

## 为什么做

底层 judge 与 sandbox 已能执行和汇总判题，但还没有一条从浏览器到异步判题结果的完整用户链路。
本功能交付传统 OJ 的第一个可演示纵向切片，为后续 CORE 模式和题目生产工作台建立真实基础。

## 使用者

普通答题用户希望在同一个工作台完成读题、编码、自测和提交，能够看懂提交当前处于排队、判题还是
完成状态，并区分代码错误、答案错误和系统故障。

单管理员需要准备并发布一道题来验证传统 OJ 完整链路。MVP 允许管理员作为作者自行审核发布，但仍需
保留发布版本以及提交实际使用的题目版本和判题环境。

## 入口

管理员从题目管理入口创建并发布 A+B；普通用户登录后从题库进入题目详情，再进入代码编辑、自测、
正式提交、提交详情和“我的提交”。

## 正常流程

```text
管理员创建 A+B 草稿
  → 配置题面、样例、C++、隐藏测试和限制
  → 预览并发布不可变版本

普通用户登录
  → 在题库找到 A+B
  → 阅读题面并选择 C++
  → 编写完整程序
  → 使用自定义 stdin 自测
  → 查看 stdout / stderr / 资源结果
  → 正式提交
  → 查看 Pending / Judging / Done
  → 查看 AC、WA 或 CE 等终态及允许公开的信息
  → 在我的提交中找到本次记录
```

## 业务规则

- REQ-001：ACM 用户提交包含完整程序入口并自行处理标准输入输出。
- REQ-002：本工作只开放已经完成验证的 C++，其他语言不出现在选择项中。
- REQ-003：自定义测试不计入正式提交和题目通过状态。
- REQ-004：正式提交创建后绑定实际使用的题目版本、语言、限制快照和判题环境。
- REQ-005：发布后的题目版本不可原地覆盖，修改产生新版本。
- REQ-006：正确程序为 AC，编译失败为 CE，输出错误为 WA；系统故障不得伪装成用户答案错误。
- REQ-007：隐藏输入和标准答案不得向普通用户泄漏。
- REQ-008：verdict 除颜色外必须有文字或符号表达。
- REQ-009：重复刷新页面不能创建新的提交。
- REQ-010：自定义测试和正式提交拥有清晰不同的入口、状态和记录语义。

## 边界与失败

题库和提交列表必须区分加载中、暂无数据、加载失败并可重试、未登录或无权限和正常结果。

提交详情必须区分请求尚未成功创建、已创建但仍在排队、正在判题、用户程序终态、平台系统故障，
以及结果暂时拉取失败但提交仍然存在。查询失败不能把已有提交变成失败状态或创建重复提交。

## 要求

- REQ-011：提交和判题生命周期可追溯且重复消费保持幂等。
- REQ-012：页面和 API 只公开产品允许的信息，编译诊断经过安全处理。
- REQ-013：列表、详情和操作拥有明确的 loading/empty/error/unauthorized/success 状态。
- REQ-014：内部 MVP 记录正式提交成功率、系统错误率和从创建到终态的耗时分布，先建立基线而不虚构 KPI。

## 验收标准

- AC-001（管理员发布）：管理员创建 ACM A+B，填写题面和样例，配置隐藏 `.in/.out`、C++ 与有效限制
  后发布；用户题库出现该题，发布版本有稳定标识，再次编辑不能覆盖已发布版本。
- AC-002（正确自测）：用户以 `1 2` 自测正确完整 C++ 程序；页面显示 stdout `3`、运行状态和允许
  公开的资源信息，“我的正式提交”没有新增记录。
- AC-003（正式 AC）：用户正式提交正确代码；只创建一次提交，页面展示从排队/判题到 AC 的生命周期，
  “我的提交”可找到它，并能追溯本次题目版本和环境。
- AC-004（编译错误）：缺少必要语法的 C++ 正式提交终态为 CE，显示安全处理的诊断，不显示为 WA 或
  平台故障。
- AC-005（答案错误）：始终输出错误结果的可编译程序终态为 WA，页面不泄漏隐藏输入或标准答案全文。
- AC-006（查询暂时失败）：已经创建的提交在一次查询失败后可重试恢复，不创建重复提交，也不把状态
  伪装成 WA。

## 不做什么

- CORE 代码模式；
- Python、Java 或其他语言；
- AI 出题、生成器、校验器和多语言标定工作台；
- 收藏、排行榜、竞赛、课程、讨论和社交能力；
- 复杂审核分权、评论和批量运营；
- SPJ、部分分、交互题和 hack 数据；
- 性能对比与个人统计。

## 待确认项

- UNKNOWN-001（blocking）：MVP 登录采用开放注册还是管理员预置账号。
- UNKNOWN-002（blocking）：普通用户在 WA 时允许看到多少测试点信息。
- UNKNOWN-003（blocking）：内部 MVP 的发布环境口径。

这三项会改变用户行为、安全边界或验收方式，进入 review/approved 前必须由产品负责人解决。
