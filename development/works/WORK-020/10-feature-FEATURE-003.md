# FEATURE-003：搭建用户端与管理端应用布局

## 为什么做

当前页面都挂在同一个临时顶部导航下，普通用户和管理员没有清晰的空间边界。随着题库、提交、题目运营
等页面增加，这会让导航不断堆叠，也无法用分组与子菜单表达管理任务。本功能先提供稳定、可复用、可
响应的双端应用骨架，后续业务页面只负责自己的内容。

## 使用者

- 访客与普通用户：在首页、登录、账号和未来答题页面之间使用一致的顶部导航、内容区和页脚。
- 管理员：进入独立管理空间，通过左侧分组导航和子菜单切换管理页面，并可返回普通用户端。
- Web 开发者：新增页面时选择用户端或管理端壳层，不再复制页头、账号状态、页脚和响应式导航。

## 入口

- 普通用户端覆盖 `/`、`/login`、`/account/password`、`/forbidden` 以及后续非 `/admin/*` 业务页面。
- 管理端覆盖 `/admin/*`，继续先通过 ADMIN 权限检查；`/admin` 与 `/admin/dashborad` 都展示同一个
  Dashboard 页面。Dashboard 初期不承载统计、图表或业务卡片。
- ADMIN 可从用户端账号区域进入管理端，也可从管理端明确返回用户端；USER 看不到可操作的管理入口。

## 正常流程

```text
访问普通页面
  → 看到用户端 Header
  → 在 Main 完成当前页面任务
  → 通过 Footer 获得稳定页面收尾

ADMIN 进入 /admin/*
  → 通过权限检查
  → 看到管理端 Header
  → 在 Main 左侧展开管理分组、选择子菜单
  → 在 Main 右侧完成管理任务
  → 页面底部显示管理端 Footer
```

## 业务规则

- REQ-001：用户端采用唯一的 `header → main → footer` 结构；页面内容通过嵌套路由进入 `main`，不得在
  各业务页重复创建全局页头或页脚。
- REQ-002：管理端采用唯一的 `header → main(sidebar + content) → footer` 结构；桌面左侧导航与右侧
  内容同时可见，业务页只渲染右侧内容。
- REQ-003：用户端与管理端是两棵互斥路由壳层；任一页面不能同时出现两套 Header、两个 Main 或两套
  全局导航。
- REQ-004：管理导航数据支持“分组 → 一级项 → 二级项”结构。本阶段最多两级；有子项的一级项是展开
  按钮，叶子项是路由链接，不制造既导航又展开的混合控件。
- REQ-005：访问二级页面时，所属父项自动展开，叶子链接使用 `aria-current="page"`；用户可以独立折叠
  非当前分组，当前项不能只靠背景色识别。
- REQ-006：管理导航先提供一级叶子项 `Dashboard`，它在 `/admin` 与 `/admin/dashborad` 都保持当前状态；
  首个实际子菜单使用已有能力“账号管理 → 用户账号”，链接到 `/admin/users`。不得为了填满边栏伪造
  题目管理、提交监控或系统设置页面。
- REQ-007：用户端 Header 包含品牌、当前可用的主导航和账号动作；管理端 Header 明确标识“管理中心”，
  提供侧栏开关、返回用户端和账号动作。两端 Footer 文案简短，不新增未确认的法律或营销链接。
- REQ-008：现有 Session pending/error、访客登录、首次改密、ADMIN 入口、退出中/失败行为保持；管理端
  在 ADMIN 权限确认前不闪现管理导航或内容。
- REQ-009：登录、改密、403、404 和用户管理的业务规则与数据请求不因壳层迁移而改变。`/admin` 与
  `/admin/dashborad` 复用同一个 Dashboard 页面组件，不通过重定向改变地址，也不请求业务数据。
- REQ-010：本工作中的页面结构不改变 WORK-019 已交付主页内容定义，但取代其“用户主页使用侧栏”的
  Web 壳层方向；未来 Web 用户端以本功能的传统顶部导航结构为准。

## 边界与失败

- 320px 下用户端主导航和管理端侧栏改为菜单按钮触发的可关闭面板；关闭后焦点回到触发按钮，页面不
  产生横向滚动。
- 管理子菜单展开失败或 JavaScript 尚未接管时，导航仍应有可理解的分组和可到达叶子链接；不能只显示
  无标签图标。
- Session 查询失败时保留稳定壳层和重试动作，不把失败状态当成访客；退出失败继续显示错误并允许重试。
- USER 直接访问 `/admin/*` 仍跳转 403；未登录用户仍安全返回登录页，首次改密用户仍先进入改密页。
- 内容很短时 Footer 贴近视口底部；内容很长时随文档流向下，不覆盖表格、弹窗或分页。

## 要求

- REQ-011：优先采用项目 `base-nova` 配置对应的 shadcn/ui Sidebar、Collapsible、Sheet/相关依赖组件；
  生成源码必须按 Cherry OJ 组件合同覆盖，底层继续使用现有 Base UI，不引入 Radix 第二套 primitive。
- REQ-012：所有样式只消费 `apps/web/design-system/` 已提供的 semantic token 与 Tailwind alias；禁止 raw
  hex/OKLCH、主题 id 分支、`.dark`、颜色透明度捷径和新的 sidebar 私有颜色真源。
- REQ-013：`cherry-black` 与 `pure-white` 保持相同 DOM anatomy、尺寸语义、交互和状态；不新增主题切换器。
- REQ-014：每页只有一个可命名 `main`；提供“跳到主要内容”链接，导航顺序遵循 DOM，菜单按钮暴露
  可访问名称、`aria-expanded` 与控制关系，Escape 可关闭窄屏面板。
- REQ-015：320px、200% 缩放、长中文、键盘、reduced-motion 和 forced-colors 下，品牌、当前位置、菜单
  开关、主要内容与退出动作仍可使用；必要图标与焦点达到设计系统对比要求。
- REQ-016：不因应用壳层额外请求业务 API；Session 继续复用 TanStack Query 缓存，移动端导航开关只用
  局部状态或 shadcn Sidebar provider，不引入新的全局状态库。
- REQ-017：Dashboard 初期只保留页面级 `Dashboard` 标题，内容区可以为空；不展示虚构的用户数、提交数、
  判题状态、图表、快捷操作或服务健康数据。

## 验收标准

- AC-001（用户端桌面）：以访客、USER 和 ADMIN 三种 Session 打开 `/`，均只出现一个 Header、Main、
  Footer；账号动作符合身份状态，页面短内容时 Footer 位于窗口底部。
- AC-002（管理端桌面）：ADMIN 打开 `/admin/users?page=1`，看到管理 Header、左侧导航、右侧“用户账号”
  内容和 Footer；“账号管理”展开，“用户账号”具有当前页语义，不出现用户端全局 Header。
- AC-003（子菜单键盘）：仅用键盘可聚焦并展开/折叠“账号管理”，进入“用户账号”，返回后当前父项保持
  展开；焦点轮廓清楚且状态不只靠颜色。
- AC-004（窄屏）：在 320px 打开用户端与管理端，页面无横向溢出；管理侧栏默认不挤压内容，可由 Header
  菜单按钮打开，以 Escape/选择链接关闭并把焦点恢复到合理位置。
- AC-005（权限与状态）：Session pending/error、首次改密、未登录访问管理端、USER 越权、退出失败都
  保持已有安全行为，管理内容不会在权限确认前闪现。
- AC-006（设计系统）：两套登记主题中的壳层 anatomy 与交互一致；源码门禁未发现 raw 色值、主题分支、
  disabled opacity 或未登记设计语义，shadcn 默认样式已全部映射到项目 token。
- AC-007（回归）：现有登录、改密、用户管理和 404 E2E 继续通过；新增组件测试覆盖 landmark、当前项、
  子菜单与移动导航，生产构建和 Storybook 构建通过。
- AC-008（Dashboard）：ADMIN 分别打开 `/admin` 与 `/admin/dashborad`，两个地址均显示同一个 Dashboard
  页面结构和当前导航状态，只呈现页面标题，不请求或展示虚构业务数据。

## 不做什么

- 不设计或实现题库、题目详情、编辑器、提交列表、题目管理、判题任务或系统设置页面。
- 不改变身份、角色、权限、Session、API 或服务端契约。
- 不修改设计系统 token、主题合同、默认主题或组件 manifest；若现有语义确实不足，必须先升级设计方案。
- 不提供用户自定义侧栏宽度、拖拽调整、图标折叠记忆、主题切换或导航偏好持久化。
- 不把 Footer 做成营销站点式多列链接区，也不新增注册、排行榜、竞赛、课程或 AI 宣传入口。

## 待确认项

无阻塞项。当前确认范围：普通页面统一进入用户端上中下壳层；`/admin/*` 进入独立管理壳层；`/admin`
与 `/admin/dashborad` 复用空 Dashboard；移动端导航使用抽屉；管理菜单最多两级，首个子菜单只承载现有
“用户账号”。
