# REQ-0001：用户可以完成 C++ ACM 答题闭环

## 一句话结果

管理员发布一道 C++ ACM A+B 后，普通用户可以在浏览器中找到题目、编写和自测代码、正式提交，
并看到可信且可追溯的判题结果。

## 目标用户与使用场景

普通答题用户希望在同一个工作台完成读题、编码、自测和提交，能够看懂提交当前处于排队、判题还是
完成状态，并区分代码错误、答案错误和系统故障。

单管理员需要准备并发布一道题来验证传统 OJ 完整链路。MVP 允许管理员作为作者自行审核发布，
但仍需保留发布版本以及提交实际使用的题目版本和判题环境。

## 问题与依据

judge 与 sandbox 已经能完成底层执行和 verdict 汇总，但当前尚不能证明普通用户能通过 Web 和 Server
完成一次真实答题。PRD 阶段 1 要求分别跑通一个 C++ ACM 题和一个 C++ CORE 题，本需求只覆盖 ACM
纵向切片，不把 CORE 或题目工厂提前混入。

## 用户流程

```text
管理员创建 A+B 草稿
  → 配置题面、样例、C++、隐藏测试和限制
  → 预览并发布不可变版本

普通用户登录
  → 在题库找到 A+B
  → 阅读题面并选择 C++
  → 编写完整程序
  → 使用自定义 stdin 自测
  → 查看 stdout / stderr / 资源结果
  → 正式提交
  → 查看 Pending / Judging / Done
  → 查看 AC、WA 或 CE 等终态及允许公开的信息
  → 在我的提交中找到本次记录
```

## 产品规则

- ACM 用户提交必须包含完整程序入口，并自行处理标准输入输出；
- 本需求只开放 C++，未完成验证的语言不得出现在选择项中；
- 自定义测试不计入正式提交和题目通过状态；
- 正式提交创建后绑定实际使用的题目版本、语言、限制快照和判题环境；
- 发布后的题目版本不可原地覆盖；
- 正确程序得到 AC，编译失败得到 CE，输出错误得到 WA；
- 系统故障不得伪装成用户答案错误；
- 隐藏输入和标准答案不得向普通用户泄漏；
- verdict 除颜色外必须有文字或符号表达；
- 重复刷新页面不能创建新的提交。

## 体验状态

题库和提交列表必须区分加载中、暂无数据、加载失败并可重试、未登录或无权限和正常结果。

提交详情必须区分请求尚未成功创建、已创建但仍在排队、正在判题、用户程序终态、平台系统故障，
以及结果暂时拉取失败但提交仍然存在。查询失败不能把已有提交变成失败状态或创建重复提交。

## 范围

### 本次包含

- 满足主流程所需的最小登录或管理员预置账号能力；
- 管理员创建、预览并发布一题 C++ ACM A+B；
- 普通用户题库列表、题目详情和基本通过状态；
- C++ 完整程序编辑和自定义测试；
- 正式提交、异步生命周期、结果详情和我的提交；
- AC、CE、WA 和至少一种平台故障的正确区分；
- Submission 对题目版本、环境和限制的追溯；
- 主流程所需的加载、空数据、失败和权限反馈。

### 本次不包含

- CORE 代码模式；
- Python、Java 或其他语言；
- AI 出题、生成器、校验器和多语言标定工作台；
- 收藏、排行榜、竞赛、课程、讨论和社交能力；
- 复杂审核分权、评论和批量运营；
- SPJ、部分分、交互题和 hack 数据；
- 性能对比与个人统计。

## 产品验收场景

### 场景 A：管理员发布 A+B

前提：管理员已登录，系统存在可用 C++ 环境。

操作：管理员创建 ACM A+B，填写题面和样例，配置隐藏 `.in/.out`、C++ 和有效限制，然后发布。

结果：用户题库中出现该题；发布版本拥有稳定标识；再次编辑时不能静默覆盖已发布版本。

### 场景 B：用户自测正确代码

前提：用户打开已发布的 A+B。

操作：用户输入完整 C++ 程序，以 `1 2` 作为自定义 stdin 运行。

结果：页面显示 stdout `3`、运行状态和允许公开的资源信息；我的正式提交中没有新增记录。

### 场景 C：用户正式提交并 AC

前提：用户已经完成正确代码。

操作：用户点击提交并停留或重新进入提交详情。

结果：提交只创建一次；页面展示从排队或判题到完成的生命周期；终态为 AC；我的提交能够找到该记录；
记录可以追溯到本次实际使用的题目版本和环境。

### 场景 D：编译错误

前提：用户提交缺少必要语法的 C++ 程序。

操作：用户正式提交。

结果：终态为 CE，并显示经过安全处理的编译诊断；不会错误显示为 WA 或平台故障。

### 场景 E：答案错误

前提：用户提交始终输出错误结果的可编译程序。

操作：用户正式提交。

结果：终态为 WA；页面不泄漏隐藏输入或标准答案全文。

### 场景 F：结果查询暂时失败

前提：提交已经创建，但页面某次结果查询失败。

操作：用户重试或刷新。

结果：页面明确说明结果暂时无法获取并提供恢复方式；不会创建重复提交，也不会把状态伪装成 WA。

## 成功信号

内部 MVP 先记录基线，不预设虚假 KPI：

- 完整主流程能否在同一演示环境中重复通过；
- 正式提交创建成功率；
- 判题系统错误率；
- 从提交创建到终态的耗时分布；
- 自定义测试和正式提交是否被正确区分；
- 产品验收过程中发现的流程断点数量。
