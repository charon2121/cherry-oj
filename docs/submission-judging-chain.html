Submission → Judging

提交与判题链路

一条以本地事务、Outbox / Inbox、租约与 fencing token 组成的可靠异步链路。目标不是追求“恰好一次”，而是在重复投递、进程崩溃和网络超时下仍然得到正确结果。

202 Accepted提交即返回，判题在后台异步推进；客户端只观察稳定的产品状态。
01

接收提交并校验身份

Browser → Gateway → Submission

Gateway 完成登录态校验，Submission 校验 Idempotency-Key、题目、语言与源码大小。

  • 同一用户 + 同一 key 重放：返回原提交。
  • 同一 key 但请求体不同：返回 409 Conflict。
02

冻结本次判题配置

Submission → Problem

同步读取当前可判题版本，并冻结 problemRevisionId、CPU / 内存限制、checker、测试数据版本和允许语言。

配置不可漂移读取失败不创建提交
03

一次提交，一次本地事务

Submission + submission_db

写入 Submission(Pending)、冻结后的 SubmissionJudgeInput、幂等记录和 JudgeRequested Outbox。

事务 A源码留在 MySQL返回 202 + Location
04

Outbox 投递判题请求

Relay → Kafka

Relay 通过 FOR UPDATE SKIP LOCKED 领取待发事件，发布到 judge.requests.v1，消息 key 为 submissionId。

允许重复投递不丢事件
05

幂等创建判题任务

Kafka → Judging + judging_db

消费者在短事务中插入唯一 Inbox(eventId) 和 JudgeTask(Ready)，提交后再确认 offset；重复消息由 Inbox 消化。

事务 B消费线程不执行判题
06

Worker 以租约领取任务

Judging Worker → Submission → Go Judge

领取 Ready / RetryWaiting，写入 leaseToken、leaseUntil、attemptNo 后立即提交；再读取冻结输入并在事务外调用 Go Judge。

lease + fencingJudgeStarted
07

落库结果并生成生命周期事件

Go Judge → Judging + judging_db

仅当前 leaseToken 可完成任务。有效结果进入 Succeeded；网络错误 / 5xx 进入退避重试；协议错误或耗尽重试进入 Dead。

事务 CJudgeCompleted / JudgeFailed
08

投影为用户可见状态

Kafka → Submission + submission_db

同一事务写 Inbox 并条件更新 Submission / case results。重复、过期、非当前任务结果直接忽略，Done 永不回退。

事务 D前端轮询 verdict

不可破坏的约束

  1. 01MySQL + Kafka 采用至少一次投递，正确性来自幂等。
  2. 02数据库事务内不执行长时间 HTTP 调用。
  3. 03源码不进入 Kafka，只传标识符。
  4. 04迟到 Worker 必须被 leaseToken 隔离。
  5. 05题目配置按提交冻结，后续修改不影响在途任务。
  6. 06用户提交状态与基础设施任务状态分离。

状态机

Submission · 产品状态
Pending→Judging→Done + verdict
JudgeTask · 调度状态
Ready→Running→Succeeded
Running→RetryWaiting↺Dead

重试耗尽后，对用户映射为 Done + SE，不暴露第四种产品状态。

故障不是例外路径

每一个可能中断的位置，都有明确的恢复动作和幂等边界。

Problem 服务不可用无法取得可判题版本，Submission 尚未落库。
入口失败返回 503；客户端可用相同 Idempotency-Key 安全重试。
Relay 已发 Kafka，未标记 Outbox重启后再次发送同一事件。
重复投递Judging Inbox 以 eventId 唯一约束去重。
Judging 已提交，未确认 offsetKafka 再次投递 JudgeRequested。
重复消费Inbox 命中后直接确认，不创建第二个任务。
Worker 判题期间崩溃任务停留在 Running，租约最终过期。
租约恢复Sweeper 将任务转为 RetryWaiting，由新 Worker 领取。
旧 Worker 迟到回写新 Worker 已经取得下一份租约。
并发竞争更新条件必须匹配当前 leaseToken；旧结果丢弃。
Judge 网络超时 / 5xx调用是否已执行可能未知。
可重试1s / 10s / 60s 退避，默认最多 3 次；只允许当前租约发布结果。
Judge 返回 4xx / 协议错误通常是请求或服务契约问题。
不可盲重试任务进入 Dead，告警并将提交映射为 Done + SE。
Completed 重复或迟到生命周期事件被重复投递或顺序过期。
投影保护Submission Inbox 去重；条件更新保证 Done 不回退。
生命周期消息无法解析毒消息持续阻塞消费分区。
Poison message投递到 judge.lifecycle.dlt，保留原始载荷并触发告警。
核心判断：重复执行本身可以接受，重复落结果不可以。调度层用租约决定“谁现在有权工作”，结果层用 fencing token 决定“谁有权生效”。

四个原子事务

A 接收提交

Submission + JudgeInput + 幂等记录 + JudgeRequested Outbox。

B 创建任务

Judging Inbox + JudgeTask(Ready)，提交后确认 Kafka offset。

C 完成尝试

条件更新 JudgeTask + JudgeAttempt + 生命周期 Outbox。

D 投影结果

Submission Inbox + 条件更新 Submission 与 case results。

对客户端的稳定契约

POST

/api/submissions → 202 Accepted，响应中返回 submissionId，并设置 Location。

GET

/api/submissions/{id} → 只暴露 Pending / Judging / Done + verdict，不泄露内部重试状态。
