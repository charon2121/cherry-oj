TanStack-first SPA Gateway BFF

Cherry OJ
前端架构

面向题目浏览、代码编辑和异步判题流程的 React 应用。前端按用户工作流组织，只访问 Gateway，不感知后端微服务拓扑。

核心原则 状态只有一个所有者；页面刷新后，用户仍能从 URL 和 Submission ID 恢复任务现场。

用户主链路

01 题库

筛选与分页放在 URL，可分享，也能正确响应前进和后退。

02 · CORE 题目工作台

题面、Monaco、语言选择、样例运行与提交汇聚于一个工作区。

03 创建 Submission

携带 Idempotency-Key，经 Gateway 写入后端，安全处理重复操作。

04 判题进度

Query 首期轮询；进入终态立即停止，后续再按需要升级 SSE。

05 结果详情

展示 verdict、耗时、内存、测试点以及可解释的错误状态。

设计底线

  • 前端只调用 /api，Gateway 隐藏全部服务地址。
  • 路由守卫改善体验，但不能替代服务端鉴权。
  • 服务端状态不复制进全局 store，避免双真源。
  • 长流程必须能从 Submission ID 恢复。
  • 所有 verdict 都显式处理，不能只有 AC / WA。

前端分层

页面是用户流程的组合，而不是后端微服务的镜像。依赖方向从装配层流向业务与基础设施边界。

Routes TanStack Router

URL、页面边界、鉴权守卫、search params 与路由级加载状态。

Features 业务模块

auth、problems、submissions、profile、admin；组件与用例就近组织。

Server state TanStack Query

请求、缓存、Mutation、失效、轮询；组件不在 Effect 中直接 fetch。

UI system shadcn/ui + Tailwind

设计 token、基础组件、语义样式与无障碍；Monaco 作为独立重型组件。

API boundary Typed fetch + Zod

只访问 Gateway；统一错误、CSRF、取消、运行时校验和契约类型。

路由区域

公开区/ · /problems · /problems/$id

题库和题面允许匿名浏览；公开提交详情按产品策略脱敏源码。

用户区/workspace/$problemId · /submissions · /profile

路由守卫只控制导航体验，真正权限由 Gateway 与服务端执行。

管理区/admin/problems · /admin/users · /admin/submissions

按角色懒加载；管理组件不进入普通用户首屏 bundle。

MVP

先完成登录态恢复、题库、题目工作台、幂等提交、提交详情与判题轮询。管理后台、SSE、虚拟列表和复杂统计全部后置。
