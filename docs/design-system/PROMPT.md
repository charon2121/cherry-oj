# Cherry OJ Web 页面与组件提示词

你要为 Cherry OJ 写 Web 页面或组件。视觉目标是 **instrument panel**：近黑或纯白画布、冷灰层级、
高信息密度、严格对齐、hairline 分隔、克制圆角、几乎无动效。参照物是 Linear 这类工程工具，
不是后台管理模板，也不是营销页。

会话内只需一句话时用：**「按 `docs/design-system/PROMPT.md` 的三层来源和页面语法写；
完成后逐条回答自检六问。」**

## 三层来源，顺序不可颠倒

1. **结构与可访问性 = shadcn 官方实现**（style `base-nova`）。新增第 2 层基础组件前先查
   `https://ui.shadcn.com/r/styles/base-nova/<name>.json`：返回 200 就以官方 DOM、props 和
   可访问性行为为骨架，404 才手写并在组件清单记下依据。不重写官方结构。
2. **样式 = 本仓库语义 token**，通过 Tailwind alias 消费。只替换官方的颜色与尺寸 class。
3. **构图 = 下面的页面语法。** 这一层决定"像不像"。token 全对而构图错，判定为不合格——
   这个仓库为此返工过四轮。

## 先选模板，不要从零件现拼

第 3、4 层已经有实现，**页面不再自己拼列表和工具条**：

| 要写什么 | 用什么 |
|---|---|
| 列表页 | `ListPageTemplate` + `Toolbar` + `DataList` |
| 详情页 | `DetailPageTemplate` |
| 长任务工作台 | `WorkbenchPageTemplate`（含持续可达的保存状态栏） |
| 对齐的数据列表 | `DataList`（列定义 + 优先级 + 状态点） |
| 列表工具条 | `Toolbar` + `ToolbarFilterGroup` |

页面模板独占首内容间距（24px）和页面语义标题；页面不再自写 `pt-*`，也不再自己写
`<h1 className="sr-only">`。

## 先记住一句话

**用位置说话，不用装饰说话。装饰只在表达「层」的时候出现。**

框、线、ring 都是在用画边界说「这些是一组」「这个是激活的」。对齐用摆位置说同样的话。
下面九条都是这一条的推论（规范正文见 `design-system.md` §7.2）：

| | 规则 | 判据 |
|---|---|---|
| A | 分组靠间距不靠容器 | 一屏里"框"的数量接近 0；组内 8px、组间 24px |
| B | 状态只改颜色不加东西 | hover/focus/selected 前后元素尺寸不变，不推挤相邻元素 |
| C | 强调只有提亮和变灰 | 不加粗、不放大、不上色；列表行最亮的是标题 |
| D | 尺寸档位要少 | 不发明新高度；图标只有 14 / 16 两种 |
| E | 对齐可见内容的边缘 | 工具条标题、分组带标签、行首图标左边缘在同一竖线上 |
| F | 空白是内容 | 列表下方的空白不填；两簇之间的空白不塞列 |
| G | 颜色只管层级和状态 | 分组不用颜色；强调不用颜色；品牌色只用于主操作和当前项 |
| H | 动效只做颜色 | 无位移、无缩放；浮层可用透明度 + 极小位移 |
| I | 只有浮层允许厚重 | 浮层用 1px 边框 + 大柔阴影 + backdrop blur；其余一律无阴影 |

**焦点是 1px、贴边、换成 focus 色。** 有边框的控件让边框变色；没边框的用 1px 零偏移 outline。
不叠 ring、不加 offset、不用光晕——这是有意放弃 WCAG AAA（2.4.13）换取视觉一致，AA 仍满足。

## 页面语法（判定用，不是建议）

**列表页 = 工具条 + 数据列表 + 分页。**
工具条第一行放标题、准确计数、搜索；第二行放过滤器与 toolbar 按钮。
**过滤即时生效，不放「筛选」提交按钮**——除非查询确实昂贵，并在对应 DESIGN 里说明什么算昂贵。
文本输入回车即应用（提交按钮 `sr-only`），下拉选中即应用。

**数据列表是对齐的列**，不是卡片网格，不是 `flex-wrap`。列宽由列定义声明并跨行共享。
**声明列宽必须配 `table-fixed`**：`table-layout: auto` 会把列宽降级成"建议"，内容一长就撑开，
列边缘跨行对不齐。度量值与标识列固定一行、超出省略，否则行高随内容跳动。
行内边距 11px / 16px，行间 1px hairline（`border-line`），不用卡片间距。

**卡片是半透明的**（`bg-surface-translucent` + 1px 边框），不是不透明大块。普通分组优先用间距、
对齐和分隔线，不要每个分组都套一个 `Card`。浮层才用 `elevation-dialog`。

**层级靠明度台阶和留白建立，不靠阴影。** 无渐变、插画、纹理、噪点、毛玻璃。

**文字四档各司其职**，一屏只用两档即为层级塌陷：

| 档 | class | 用途 |
|---|---|---|
| 1 | `text-foreground` | 页面/条目主标题，一眼扫到的 |
| 2 | `text-fg-2` | 正文、列表行标题 |
| 3 | `text-fg-muted` | 次要说明、占位符 |
| 4 | `text-fg-meta` | 标识、时间戳、计数等查证用信息 |

第五档 `text-fg-disabled` **不参与这个排序**，它是另一类对象——"不可用"。它是全系统唯一豁免
4.5:1 对比度的前景色（WCAG 2.2 SC 1.4.3 对失效控件的文字不作要求），因此**禁止**把它当作
"更浅的第五档正文"使用。禁用控件旁必须另有可读的原因说明，不能只靠这个颜色。

**度量值用 mono 并给准确数字**：`42 ms`、`14 / 14`、`23%`、题目标识。不写"很快""大量"。

**状态用形状，不只靠颜色**：8px 实心圆=完成、8px 空心圆=进行中、2px 圆角方块=未开始。
难度这类有序量用颜色区分**并保留文字**。不要把一行信息全做成同色 Badge——那样等于没有层级。

**品牌红只用于主按钮、focus、正文链接和活动态。** 列表行标题用 `text-fg-2` + hover 提亮，
**不用品牌色**：一屏几十行标题全是 Cherry 就成了来源明确禁止的"大面积色块"。
品牌色也不代替 `destructive`。

**只有 opacity / color / background-color 参与动效**，150/200/320ms 标准 easing。
无位移、缩放、弹跳、入场动画、视差；`reduced-motion` 下归零。

**文案**：中文简洁陈述句，动词开头（"提交"、"重新判题"），无感叹号和 emoji。
报错说清原因和下一步——"第 14 个测试点答案错误"，不是"出错了"。

## 禁止

- **业务页面里出现 `var(--ds-*)`。** lint 规则 `ds-var-outside-ui` 会拦。缺 alias 就去
  `apps/web/design-system/tailwind-v4.css` 补，或者说明此处应该有一个组件——不要加例外。
  `calc()` 里的布局math 用 `var(--space-6)`、`var(--layout-header)`、`var(--layout-sidebar)`。
- **新增 alias 后忘记在 `src/lib/utils.ts` 的 `extendTailwindMerge` 登记。** `cn()` 认不出自定义
  键会把它和同前缀的类当成冲突组互相覆盖，样式**静默消失**，构建和测试都不报错。
- inline style、手写 `<svg>`、`onMouse*` 维护视觉状态、`Math.random()` 生成 id、`dark:`、
  枚举 theme id、raw hex / oklch、用 `color-mix()` 制造必要对比、用 opacity 表达 disabled。
- 引用不存在的 `--ds-*`。CSS 对未定义变量是静默的，样式直接消失；已有校验会拦。
- **给 focus 加 ring、加 outline offset、加光晕。** 焦点是 1px 贴边变色。
- **给非浮层元素加阴影。** 阴影只属于浮层。
- **用框表达分组。** 先用间距；间距不够就把档位差拉大，不要加框。
- 页面顶部"眉题 + 标题 + 描述"介绍区。页面直接进入任务。
- 把长 Markdown 或代码放进 `Textarea`；用项目的 `TextEditor`。
- 把来源 `ui_kits/` 的原型代码当生产实现（inline style、CDN、随机 id、可点击 `div`），
  也不要在构建、测试或生产链路里执行它。

## 交付前自检（逐条作答，不接受"已遵守"）

0. **这一屏画了几个框？** 每一个都要说出为什么间距解决不了。
1. 这是列表 / 详情 / 工作台中的哪一种？用的是哪个页面模板？如果一个都没用，为什么？
2. **列是否跨行对齐？** 截一张图，列边缘能连成竖线吗？声明了列宽却没加 `table-fixed` 吗？
3. **这一屏用了几档文字色？** 只有两档就是层级塌陷。`fg-disabled` 有没有被当成第五档正文用？
4. 我写了几处 `var(--ds-*)`？每一处为什么不能用 alias 或组件表达？
5. 新增的 alias 在 `extendTailwindMerge` 里登记了吗？
6. 两个主题、320px、200% 缩放、键盘、长中文、forced-colors、reduced-motion 分别验过没有？
   窄屏的降级方式是折行还是裁切？
7. 与冻结来源 `source/claude-design-v1/ui_kits/app/` 里同类界面的**代码数值**逐项对过没有
   （行内边距、列宽、状态点尺寸、mono 用在哪些字段）？最明显的三处差异是什么，能否消除？

> 第 7 条目前只能对照来源代码里的数值：来源原型需要从 CDN 加载 React 与 Babel 才能运行，
> 而现行规则要求"对照来源但不执行其 demo"。是否允许一次性本地渲染以做同画面对照，
> 尚未决定；在决定之前不要自行执行它。

## 验收方式

不要用"token 通过校验"证明构图正确——那正是此前四轮返工时每次都通过的检查。
改动外观时截图对照；怀疑有偏差时逐元素 dump 计算样式再 diff，它能指到具体是哪个元素的
哪个属性从多少变成了多少，而截图只能告诉你"有问题"。
