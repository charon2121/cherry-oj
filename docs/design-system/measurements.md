# 参照实测记录

## 这份文件为什么存在

设计系统当前的排版刻度、浮层材质与构图原则来自对一个**外部 Figma 文件**的实测，而那个文件
不在仓库里、访问它的凭据是一次性的。如果不把量到的数值写下来，下一个人只能看到结论
（"字号 13px"、"焦点 1px"）却无法复查依据，也无法判断某条结论是实测还是臆断——
这个仓库已经因为"照着一份说不清来源的资料做设计"返工过四轮。

**这里只记录事实（量到了什么），不记录规则（该怎么做）。** 规则在
[`../design-system.md`](../design-system.md) §7.2 与 §7.3，它们引用这里的数字。

## 尺寸档位（跨全部 frame 统计出现次数）

| 类别 | 分布 |
|---|---|
| 横向控件高度 | 32→51 次、24→26、28→17、18→11 |
| 正方形（图标位） | **16→52 次、14→35 次**，其余零星 |
| 簇内 gap | 4→76 次、8→19、9/10 少量 |

档位极少是对齐的前提：档位一多就无从判断该跟谁对齐。

## 对齐（反直觉的一条）

```
顶栏     padding-left 30px
分组带   padding-left 36px
列表行   padding-left 12px
```

三个都不一样，但视觉上对齐——列表行最左边有个平时不可见的 18px 复选框，
`12 + 18 + 5 = 35`，正好与分组带的 36 对齐。

**对齐的是文字与图标的边缘，不是容器的 padding。**

## 表单控件

描边宽度**永远是 1px**，圆角 4–6px：

| 状态 | 边框色 |
|---|---|
| 默认 | `#393a4b` |
| hover | `#444556` |
| **focus** | **`#6c79ff`（品牌色）** |

**焦点没有 ring、没有 outline offset、没有光晕**，只是那条 1px 边框换颜色。

## 浮层材质

`BACKGROUND_BLUR` 确实存在：radius **120**（命令面板遮罩）与 **30**（下拉）。

阴影：

```
_Simple Dropdown    0 7px  32px rgba(0,0,0,0.35)
_ Team Dropdown     0 4px  24px rgba(0,0,0,0.20)
Rectangle 3         0 16px 70px rgba(0,0,0,0.50)  + BACKGROUND_BLUR 120
```

**大而柔，不是小而硬。**

## 颜色

灰阶 **27 档**，全部偏蓝紫（约 235° 色相），不是中性灰。从 `#ffffff` 到 `#131420`。

**注意：这是该文件所呈现的那一个主题。** 参照产品本身提供多个主题，包含更纯粹的黑色主题；
本仓库 `cherry-black` 保留自己的近黑中性底色，**没有采用**这套蓝紫灰阶——曾经采用过一次，
经用户指出后回退。灰阶色相属于主题选择，不是系统属性。

装饰色（低饱和，用于状态与优先级图标）：
`#00b2bf` `#eb5757` `#fa6563` `#978200` `#f2c94c` `#f2994a` `#bb87fc` `#4ea7fc`

品牌紫：`#5e6ad2` `#6c79ff` `#7477f0`。本仓库品牌色是 Cherry 红，不采用。

## 实测反驳了什么

这次实测推翻了本仓库两条曾经写进规范的规则，两条都来自更早那份二手来源包的还原丢失：

| 旧规则 | 实测事实 |
|---|---|
| "不使用 … 或 backdrop blur" | `BACKGROUND_BLUR` radius 120 与 30 明确存在 |
| "焦点使用可见的 2px outline 与 offset" | 焦点是 1px 边框变色，无 ring 无 offset |

**教训：二手还原会丢失信息，而丢失的部分容易被写成"禁止"。** 引用任何来源时，
先确认它是原件还是转述。
